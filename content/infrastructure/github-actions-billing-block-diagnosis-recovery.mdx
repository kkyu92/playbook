## 증상

모든 GH Actions 워크플로가 실패:

```
The job was not started because recent account payments have failed or your 
spending limit needs to be increased.
```

특징:
- CI, cron, workflow_dispatch **모두 동시 차단** (선택적 X)
- `gh run list` 에서 `failure` + 위 메시지
- Cloudflare 외부 trigger 도 `workflow_dispatch` 도달 후 GH Actions 에서 차단

## 진단

```bash
# 1. 최근 run 상태 확인
gh run list --limit 10 --repo <owner>/<repo>

# 2. 특정 run 원인 확인
gh run view <run-id> --repo <owner>/<repo>
# "account payments have failed" 메시지 확인

# 3. 모든 워크플로 영향 여부 확인
gh run list --limit 20 --repo <owner>/<repo> | grep -c failure
```

## 원인 분류

| 원인 | 상황 |
|---|---|
| **Free tier 한도 초과** | Private repo 2,000 min/월 소진. Public repo 무제한 |
| **결제 수단 만료** | 신용카드 만료 또는 결제 실패 |
| **Spending limit 0** | 유료 플랜 spending limit 미설정 |

## 복구

### 빠른 복구 (Private → Public 전환)

```bash
# 레포를 public 으로 전환 시 GH Actions 무제한 (public repo 정책)
# GitHub Settings → Repository → Change repository visibility
```

워커 3개 레포 동시 차단 시 → 모두 public 전환으로 즉시 복구.  
**트레이드오프**: 코드 공개. 시크릿은 GH Secrets 에 있으므로 노출 X.

### 결제 복구

GitHub Settings → Billing & plans → Actions → Spending limit 상향 또는 결제 수단 갱신.

## 재발 방지

### 1. 워크플로 자체 전략

```yaml
# 불필요한 PR preview 배포 차단 (Vercel)
# vercel.json ignoreCommand 패턴 참조
```

### 2. 조기 감지 (silent-skip-tracker 패턴)

```bash
# 정기 실행 워크플로가 fire 됐는지 확인
gh run list --workflow silent-skip-tracker.yml --limit 5
# status=skipped 또는 failure 축적 = 차단 조기 신호
```

### 3. 레포 공개 + 사용 모니터링

Private repo 워크플로가 월 2,000분 초과 예상 시 → Public 전환 선제 검토.  
LLM 에이전트 자동화 환경 (PR 반복 생성/머지) 에서 특히 빠르게 소진.

## 실행 체크리스트

```
[ ] 모든 워크플로 fail → gh run view 로 billing 메시지 확인

[ ] 빠른 복구: public 전환 (코드 공개 허용 시)

```
