## 문제

워커가 Sentry 대시보드의 "Additional Sensitive Fields" 에 PII 필드명 ("stripe", "customer_id", "discord_id", "email", "user_id" 등) 을 모두 등록했다. 의도적 테스트 이벤트 (structured context + fake PII) 발사 후 대시보드 raw JSON 검증:

| 결과   | 필드                                                                                    |
|--------|-----------------------------------------------------------------------------------------|
| ✅ 스크럽 | `contexts.auth`, `extra.oauth`, `extra.supabase.auth` (이름에 "auth"), `user.ip_address` |
| ❌ RAW 누출 | `user.{id,email,username}`, `contexts.payment.{stripe,customer_id,...}`, `contexts.integration.{discord_id,slack_user_id,webhook_url}`, `extra.supabase.user`, `extra.referrer`, `tags.{member_id,subscriber_id}` |

대부분 등록한 필드가 실제로는 매칭 안 됨. 디폴트 `@password`/`@ip`/`@bearer` 규칙이 우연히 걸린 것만 작동.

## 근본 원인

Sentry 기본 UI 의 Sensitive Fields 는:

- `request.data` 와 일부 프레임에만 매칭
- `user` / `contexts` / `tags` / `extras` 의 커스텀 nested 필드는 디폴트 규칙이 **이름 부분 문자열** 만 휴리스틱으로 잡음
- "stripe" / "customer_id" 같은 실 도메인 필드명은 디폴트 키워드와 안 겹침 → 매칭 실패

즉 대시보드 등록은 **신뢰할 수 없는 가드**. silent 통과되는 PII 가 production 에 영구 박제될 위험.

## 해결 — beforeSend 훅 + 재귀 walk

대시보드 의존을 버리고 **코드화된 가드**로 전환:

```ts
// src/sentry-scrub.ts
const SENSITIVE_KEYS = new Set([
  // 기본 PII
  "email", "phone", "username", "user_id", "id",
  // 결제
  "stripe", "customer_id", "payment_method", "charge",
  // 통합
  "discord_id", "slack_user_id", "webhook_url",
  // ...
]);

function scrub(obj: any, depth = 0): any {
  if (depth > 10 || obj == null) return obj;
  if (typeof obj !== "object") return obj;
  if (Array.isArray(obj)) return obj.map(v => scrub(v, depth + 1));
  const out: any = {};
  for (const [k, v] of Object.entries(obj)) {
    out[k] = SENSITIVE_KEYS.has(k.toLowerCase()) ? "[Filtered]" : scrub(v, depth + 1);
  }
  return out;
}

export function sentryBeforeSend(event: Sentry.Event): Sentry.Event {
  if (event.user) event.user = scrub(event.user);
  if (event.contexts) event.contexts = scrub(event.contexts);
  if (event.extra) event.extra = scrub(event.extra);
  if (event.tags) event.tags = scrub(event.tags);
  return event;
}
```

`instrumentation.ts` (서버) + `instrumentation-client.ts` (클라이언트) 양쪽에서 `Sentry.init({ beforeSend: sentryBeforeSend })` 연결.

## 가드 설계 원칙 (일반화)

본 사고는 [drift-detection-methodology](/wiki/harness-engineering/drift-detection-methodology) 의 Level 2 작동 드리프트 — "설정만 해놓고 검증 없이 넘어간 silent 실패". 관측 인프라 한정으로 일반화:

> **관측 인프라 배선은 항상 의도적 테스트 이벤트 수신 확인과 짝.** 설정만 해놓고 넘어가면 silent 실패 감지 불가.

같은 가드 B 테스트가 [Next.js instrumentation.ts 위치 silent 실패](/wiki/context-engineering/nextjs-instrumentation-location) 까지 동시에 폭로 — 가드 자체가 두 독립 버그를 한 번에 드러낸 케이스.

체크리스트:
1. 관측 도구 배선 직후 **의도적 테스트 이벤트** (예: `/_diag/sentry-test`) 발사
2. **대시보드 raw JSON 직접 확인** — 필드별 실제 매칭 여부. 자동화된 alert 만 믿지 말 것
3. **PII 가드는 코드 + 테스트 fixture** 로 회귀 방어. 대시보드 설정은 보조
