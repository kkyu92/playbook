반복 발생하는 워커 incident(moneyball CI fail, PR audit gate fail 등)을 TODOS.md 에서 추적할 때, 건당 새 항목 추가보다 카운터 갱신이 더 효율적인 패턴.

## 패턴

```markdown
## [P1] moneyball CI fix — ws/vite 취약점 (2026-06-16, 반복 누적 135건)

**What**: moneyball `pnpm audit --audit-level=high` 실패.
**Why**: CI 전체 블로킹. 허브 batch-close 누적: 164건(1110-1190) + 19건(1201) + **80건(1210)** + **1건(#2220, cycle 1310)** = **264건 총 close** (2026-07-04 갱신).
**Action (사용자 영역)**: moneyball 레포에서 `pnpm update ws vite` → CI 재확인 → push.
```

**핵심**: 항목 자체는 그대로, 카운터(264건)와 갱신 날짜만 업데이트. 이력은 git log가 담당.

## 언제 카운터 패턴을 쓰는가

| 상황 | 권장 패턴 |
|------|-----------|
| 동일 root cause의 이슈가 주 1회+ 재발 | 카운터 갱신 (이 패턴) |
| 서로 다른 root cause의 이슈 | 각각 별도 항목 |
| 이슈가 close됐고 재발 없음 | DONE 섹션으로 이동 |
| 이슈 내용/액션이 변경됨 | 기존 항목 업데이트 (신규 X) |

## 갱신 시점

`worker-incident-triage` chain에서 반복 패턴 확인 시:
1. issue close comment에 패턴 확인 명시
2. TODOS.md 해당 항목의 카운터 + 날짜 갱신
3. commit: `content: TODOS.md [P1] counter 갱신 (N건)`

## 카운터 형식 권장

```
**건수**: 164건(cycle 1110-1190) + 19건(1201) + **80건(1210)** = **263건 총 close** (2026-06-25)
```

- 배치별 소계 보존 (raw) → 감사 추적 가능
- 마지막 총계 bold → 스캔 시 즉시 식별
- 날짜 갱신 → stale 방지

## DONE 섹션 이동 기준

- Root cause가 영구 해소됐을 때 (moneyball pnpm update push 완료 등)
- DONE 항목에 해소 경위 1-2줄 기록 후 archived

## 연쇄 효과

카운터 패턴 미사용 시 TODOS.md 폭증 → 신규 항목 발견 어려움 → signal 희석. 반복 이슈는 카운터 1줄로 요약이 핵심.
