LLM 에이전트의 활용이 증대됨에 따라, 생성된 텍스트의 가독성, 명확성, 그리고 사실 전달력은 그 효용성을 결정하는 핵심 요소가 되었다. 특히 복잡한 정보나 기술적 내용을 다루는 에이전트의 경우, 사람이 쉽게 이해하고 검증할 수 있는 `Human-readable writing` 스킬은 필수적이다. 이는 단순히 문법적으로 올바른 것을 넘어, 정보의 구조화와 불확실성의 명확한 표명을 포함한다.

## Human-readable Writing 핵심 지침

긱뉴스에서 소개된 'Human-readable writing' 지침은 에이전트가 보다 정확하고 명료한 글을 작성하도록 돕는 구체적인 원칙을 제공한다. 이 지침들은 주로 압축된 정보의 확장, 조건부 정보의 배치, 그리고 사실의 유지에 중점을 둔다.

### 1. 압축된 명사구 확장 (Decompressing Noun Phrases)

LLM은 종종 간결함을 위해 명사구를 압축하는 경향이 있다. 하지만 이는 문장의 주체와 동작을 모호하게 만들어 가독성을 저해할 수 있다. 에이전트는 이러한 압축된 명사구를 주체와 동작이 명확히 드러나는 완전한 문장으로 풀어쓰도록 지시받아야 한다.

*   **예시**: 
    *   `원본`: "서비스 가용성 감소 예측"
    *   `지침 적용`: "시스템은 다음 주에 서비스 가용성이 감소할 것으로 예측한다."

### 2. 조건 및 예외의 명확한 배치 (Explicit Placement of Conditions and Exceptions)

주장이나 결론을 제시할 때, 그에 수반하는 조건, 예외, 불확실성 등을 해당 주장과 가까운 곳에 배치해야 한다. 이는 독자가 정보의 맥락을 한 번에 파악하고, 오해의 소지를 줄이는 데 기여한다.

*   **예시**:
    *   `원본`: "성능 개선이 예상된다. 네트워크 지연 발생 시에는 그렇지 않다."
    *   `지침 적용`: "네트워크 지연이 발생하지 않는다면, 시스템 성능 개선이 예상된다."

### 3. 원문 사실 및 전문 용어 유지 (Preserving Factual Fidelity and Jargon)

에이전트는 원문의 사실, 수치, 전문 용어를 임의로 변경하거나 일반화하지 않도록 해야 한다. 특히 기술 문서나 데이터 분석 결과와 같은 영역에서는 정확한 정보 전달이 최우선이다. 불필요한 의역은 정보의 왜곡을 초래할 수 있다.

### 4. 불확실한 관계 추론 금지 (Avoiding Speculative Relationships)

원문에서 불분명하거나 명시되지 않은 관계에 대해 에이전트가 추측하여 내용을 채우는 것을 엄격히 금지한다. 에이전트는 불확실한 부분은 불확실하다고 명시하거나, 정보가 없음을 밝혀야 한다. 이는 허위 정보 생성(hallucination)을 방지하는 중요한 가드레일이다.

## LLM 에이전트 통합 전략: Claude Code Harness 적용

`Human-readable writing` 지침을 LLM 에이전트에 통합하는 가장 효과적인 방법 중 하나는 시스템 프롬프트(System Prompt)에 명확한 지시로 포함하는 것이다. 특히 `Claude Code Harness`와 같이 코드 생성 및 분석 작업을 수행하는 에이전트의 경우, 명료한 설명과 조건부 로직 표현은 코드 품질과 유지보수성에 직결된다. 2026년 현재, 이러한 정제된 출력은 에이전트가 생성한 결과물에 대한 신뢰도를 높이는 데 필수적이다.

```python
# Python Example: 에이전트 시스템 프롬프트 구성 (Simplified for illustration)
system_prompt_template = """
당신은 경험 많은 기술 문서 작성 에이전트입니다. 다음 지침을 엄격히 준수하여 문서 및 코드 설명을 작성하십시오:

1.  **압축된 명사구 확장**: 모든 주체와 동작이 명확히 드러나도록 문장을 풀어 작성합니다. (예: "API 응답 지연" -> "API 서버의 응답 시간이 지연되었다.")
2.  **조건 및 예외 명확히 배치**: 조건, 예외, 또는 불확실성을 해당 주장 바로 앞에 배치하여 문맥을 명확히 합니다.
3.  **원문 사실 및 전문 용어 유지**: 제공된 원문의 모든 사실, 수치, 전문 용어는 변경 없이 그대로 사용합니다. 불필요한 의역을 피합니다.
4.  **불확실한 관계 추론 금지**: 원문에 명시되지 않거나 불분명한 관계는 추측하여 채우지 않습니다. 정보가 부족한 경우 이를 명확히 밝히거나, 가능한 경우 더 많은 정보를 요청합니다.
5.  **명확하고 간결한 Markdown 형식**: 정보를 효과적으로 전달하기 위해 헤딩, 리스트, 코드 블록을 적절히 사용합니다. 단, HTML 태그는 self-closing 형식을 따르며, JSX expression {중괄호}는 `인라인 코드`로 감쌉니다.
"""

# 이후 사용자 프롬프트 및 컨텍스트가 추가됩니다.
user_task = "다음 코드 스니펫의 기능을 설명하고, 발생 가능한 에러 케이스를 명확한 문장으로 서술하시오."
code_snippet = """
def process_data(data, config=None):
    if not data: # < 3
        raise ValueError("Input data cannot be empty")
    if config and config.get('validate'):
        # validation logic
        pass
    return len(data)
"""

final_prompt = f"{system_prompt_template}\n\n사용자 요청: {user_task}\n\n코드 스니펫:\n```python\n{code_snippet}\n```"
print(final_prompt) # 이 프롬프트가 LLM에 전달됩니다.
```

## 트레이드오프

`Human-readable writing` 지침을 에이전트에 적용하는 것은 여러 장점과 함께 고려해야 할 단점도 존재한다. 균형 잡힌 접근이 중요하다.

*   **장점: 명확성 및 정확성 향상**: 출력이 모호하지 않고 사실적 오류(hallucination)가 줄어든다.
    *   **언제 좋음**: 복잡한 기술 문서, 법률 문서, 데이터 분석 보고서 등 정확성과 검증 가능성이 필수적인 경우. 인간의 개입을 최소화하여 빠른 판단이 필요한 경우.
    *   **언제 나쁨**: 창의적이거나 은유적인 언어 사용이 중요한 경우, 간결한 요약이 필요한 경우.
*   **장점: 인간 검토 및 디버깅 용이성**: 사람이 읽기 쉽기 때문에 에이전트의 논리 흐름을 추적하고 오류를 발견하기 용이하다.
    *   **언제 좋음**: 에이전트의 행동을 감사(audit)해야 하거나, 생성된 코드/설명을 사람이 직접 수정/개선해야 하는 개발 워크플로우.
    *   **언제 나쁨**: 오직 기계적인 후처리만 필요한 경우, 인간 검토 과정이 불필요한 경우.
*   **단점: 토큰 사용량 증가 및 처리 속도 저하**: 명사구를 확장하고 조건을 명시하는 과정에서 더 많은 토큰이 사용될 수 있으며, 이는 응답 생성 시간을 늘릴 수 있다.
    *   **언제 좋음**: 높은 품질의 출력이 비용보다 중요하거나, 실시간 응답 속도가 크게 중요하지 않은 경우.
    *   **언제 나쁨**: 낮은 지연 시간(low latency)이 요구되는 애플리케이션이나, 토큰 비용이 엄격하게 제한된 환경.
*   **단점: 프롬프트 엔지니어링의 복잡성 증가**: 지침을 명확히 전달하고 에이전트가 이를 일관되게 따르도록 유도하기 위한 프롬프트 설계가 더 까다로워질 수 있다.
    *   **언제 좋음**: 초기 설정에 충분한 시간과 리소스 투자가 가능하여 장기적인 이점을 추구하는 경우.
    *   **언제 나쁨**: 빠르고 간편한 프로토타이핑이나, 프롬프트 엔지니어링 전문 지식이 부족한 팀.

## 실전 체크리스트

에이전트 글쓰기 스킬 지침을 프로젝트에 적용할 때 다음 항목들을 검증하여 성공적인 통합을 목표로 한다.

- [ ] **시스템 프롬프트 명확성 검증**: 'Human-readable writing' 지침이 시스템 프롬프트에 모호함 없이 구체적으로 명시되었는가?
- [ ] **출력물 샘플링 및 평가**: 에이전트가 생성한 출력물 샘플을 주기적으로 검토하여, 압축된 명사구가 효과적으로 확장되었는지, 조건부 정보가 올바르게 배치되었는지 평가한다.
- [ ] **사실적 오류(Hallucination) 감소율 측정**: 지침 적용 전후로 에이전트의 사실적 오류 발생률이 유의미하게 감소했는지 정량적으로 측정한다.
- [ ] **토큰 사용량 및 지연 시간 모니터링**: 지침 적용 후 토큰 사용량과 응답 지연 시간 변화를 모니터링하고, 설정한 SLA(Service Level Agreement) 내에 있는지 확인한다.
- [ ] **인간 검토 효율성 지표 추적**: 에이전트 출력물에 대한 인간 검토 시간이나 수정 사항의 양이 감소했는지 추적하여, 가독성 향상 효과를 검증한다.
- [ ] **불확실성 표명 일관성 확인**: 에이전트가 불분명한 정보에 대해 '정보 부족', '확인 필요' 등과 같이 명확하게 표명하는지 일관성을 확인한다.
- [ ] **피드백 루프 구현**: 인간 검토자로부터의 피드백을 에이전트의 학습 또는 프롬프트 개선에 반영하는 자동화된 피드백 루프가 구축되었는가?
