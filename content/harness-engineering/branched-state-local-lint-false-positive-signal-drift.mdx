BRANCHED 상태에서 `node scripts/lint-content.mjs`를 로컬에서 실행하면, 이미 origin/main에서 수정된 문제가 다시 감지된다. 수정 PR이 squash-merge된 후 로컬 main을 업데이트하지 않으면 로컬 파일은 구버전 상태를 유지하기 때문이다.

## 발생 메커니즘

```
cycle 1240: curate → orphan fix (PR #2132) → origin/main에 squash-merge
              │
              ▼
local main: 여전히 구버전 파일 유지 (PR pull 없음)
              │
              ▼
cycle 1246: curate 진단 → node scripts/lint-content.mjs
              │
              ▼
결과: 2 orphan links, 3 isolated nodes (이미 #2132로 수정됨)
```

실제 사례 (cycle 1246):
- `lint` 출력: `harness-engineering/hub-pull-evidence-tracking-from-hub-convention` → orphan 2건
- 실제 origin/main 상태: 이미 수정됨 (PR #2132, 2026-06-29T00:34 UTC 머지)
- `curate` chain 진입 → 파일 수정 시도 → stash/checkout 시 충돌 → origin 버전으로 복원 → retro-only

## 감지: 로컬 lint 신뢰성 테스트

```bash
# 현재 BRANCHED 상태 확인
git rev-list --left-right --count origin/main...main
# 출력: 25  211 → origin 25 ahead, local 211 ahead

# 진짜 origin/main 기준 lint 확인
git stash push -u -m "tmp"
git checkout -B tmp-lint-check origin/main
node scripts/lint-content.mjs 2>&1 | grep -E "Orphan|Isolated"
git checkout main
git stash pop
```

또는 더 빠르게 — `git show origin/main:<파일경로> | grep connections:`로 origin 버전 직접 확인.

## 판단 기준

| 상태 | 로컬 lint | 신뢰도 |
|------|-----------|--------|
| BRANCHED = 0 (sync) | 정확 | 100% |
| origin 1-10 ahead | 대체로 정확 | 85%+ |
| origin 10+ ahead | 확인 필요 | 70% |
| **origin 20+ ahead** | **의심** | **&lt;60%** |

origin이 20+ 커밋 앞선 상태에서 curate 진단 시 → lint 결과를 맹신하지 말고 origin 버전 교차 검증 필요.

## 적절한 대응

1. **로컬 lint 결과 확인 시**: origin/main 기준으로 교차 검증 (`git show origin/main:<file>`)
2. **curate chain 진입 전**: BRANCHED 정도 확인 (origin M ahead)
3. **origin 20+ ahead**: 로컬 fix 시도 대신 retro-only + 메모 박제 (이미 수정됐을 가능성 높음)
4. **장기 해결책**: 사용자가 `git pull --rebase origin main + git push origin main` → BRANCHED 해소

## 연쇄 영향

로컬 lint 오염은 curate chain 뿐 아니라 다른 결정에도 영향:
- **JIT search**: local embeddings.json은 구버전 기반 — 수정된 entry의 이전 내용을 반환 ([[agentic-branched-state-jit-search-accuracy-degradation]])
- **scan-promotions**: 로컬 solutions 디렉토리가 구버전 → 승격 임계 계산 오류 가능
- **새 entry 생성**: 구버전 기반 connections 추가 시 orphan 위험
