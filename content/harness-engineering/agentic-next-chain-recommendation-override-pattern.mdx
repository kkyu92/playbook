## 추천 신호의 역할

`next_recommended_chain` 은 매 사이클 retro에서 박제되는 비강제 힌트다:
- **강제 X**: 진단 결과 + chain pool 규칙이 우선
- **참고 O**: 직전 사이클 맥락을 메인(LLM)이 결정에 반영

## 합법적 오버라이드 사유

| 상황 | 추천 | 실제 선택 | 이유 |
|---|---|---|---|
| open issue 존재 | explore-idea | worker-incident-triage | 진단 우선순위 규칙 (open issue = 최우선) |
| SE pending 마커 | explore-idea | skill-evolution | 강제 발화 (마커 = 명시적 override) |
| streak guard 발동 | explore-idea | curate (강제) | 동일 chain 3회+ 연속 fail 방어 |
| 사용자 개입 | curate | (사용자 지시) | 사용자 최고 우선순위 |

## 비합법적 오버라이드 (피해야 할 패턴)

| 패턴 | 문제 |
|---|---|
| "이번엔 다른 게 더 좋을 것 같아서" (근거 없이) | 직전 맥락 무시 — 불필요한 다양성 |
| 추천을 보지 않고 chain 선택 | cycle_state carry-over 목적 무력화 |
| 항상 curate 선택 (추천 무관) | explore-idea 성장 차단 |

## 추천 신호 유지 원칙

1. **매 사이클 retro에 박제 의무**: 빠진 사이클의 다음 사이클은 carry-over 없이 맥락 손실
2. **합법적 override = 신호 약화 아님**: open issue / SE 마커 = 정상 메커니즘
3. **추천이 3 사이클 이상 계속 무시되면**: 진단 source 다양성 점검 (한 source 만 봤는지 확인)
