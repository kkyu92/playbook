## 1000 사이클에서 검증된 핵심 패턴

### 1. Git history = 불변 state store (cycle 992 evidence)

497 cycle 드리프트된 checkpoint에서도 `git log --oneline -20`으로 30초 내 완전 컨텍스트 복구. policy: 커밋 메시지가 cycle_state 역할을 수행.

→ **설계 원칙**: 중요한 상태는 구조화된 커밋 메시지에 박제. 파일 기반 checkpoint는 optimization.

### 2. Skill-Evolution steady-state oscillation (cycle 564+)

SE trigger 5 (0회 chain 명단)가 안정화되면 SKIP-FIRE-SKIP 패턴이 자연적으로 형성. 명단 변화 없을 때 SE 점유율 ≥ 40% → skip. 슬라이딩 윈도우 기반 자동 조절.

→ **설계 원칙**: 메타 작업(SE)도 phase 기반 자연 dormancy 허용. 강제 발화 = 잡음.

### 3. Chain dormancy = project phase fingerprint

고정된 0회 chain 명단 = 현재 프로젝트 도메인 반영. polish-ui/design-system이 0회인 이유는 공개 전 단계이기 때문. fix-incident/worker-incident-triage가 0회인 이유는 안정적인 인프라.

→ **설계 원칙**: 0회 chain에 강제 발화 X. 자연 dormancy는 system health 신호.

### 4. Wiki 무덤 방지 = 검색 사용률 추적

lint CLEAN + JIT Unused 0건이 wiki ROI의 실증. 생산만 있고 소비 메커니즘 없으면 무덤. search-hits.json 기반 usage tracking이 실질적 지표.

→ **설계 원칙**: entry 생성 후 JIT search hit 여부가 진짜 가치 측정.

### 5. Curate = 연결 유지 작업

explore-idea로 entry를 생성하면 orphan link, stale entry가 자연 발생. curate 주기적 실행이 graph 건강도 유지. 삭제 시 reverse-lookup 의무.

→ **설계 원칙**: create/maintain 비율 ≈ 3:1 (3 explore-idea 후 1 curate).
