Claude Code 2.1.198 버전에서 발견된 `AskUserQuestion`의 자동 진행 (Auto-Progression) 기능은 AI 에이전트 하네스 설계에서 중요한 보안 및 제어 문제를 제기합니다. 이 기능은 사용자 응답이 60초 내에 없을 경우 모델이 자체적으로 판단하여 작업을 진행하도록 기본 설정되어 있었으나, 출시 당시 변경 로그나 공식 문서에 명시되지 않아 잠재적인 위험을 내포했습니다. 사용자 권한 요청을 자동 승인하지는 않더라도, 이미 허용된 도구나 내부 API를 모델이 자율적으로 사용하여 의도치 않은 데이터 변경이나 시스템 오작동을 유발할 수 있습니다. 이는 특히 에이전트의 자율성이 증대되는 2026년 AI 트렌드에서 critical한 문제입니다.

## 자동 진행의 위험성 분석

AI 에이전트의 `AskUserQuestion`과 같은 사용자 개입 지점은 시스템의 안정성과 예측 가능성을 유지하는 핵심적인 휴먼-인더-루프 (Human-in-the-Loop) 메커니즘입니다. 이러한 지점에서 자동 진행 기능이 명시적인 사용자 동의 없이 작동한다면 다음과 같은 위험에 노출될 수 있습니다.

### 1. 의도치 않은 작업 수행 (Unintended Operations)
에이전트에게 이미 부여된 광범위한 권한이 있을 경우, 특정 작업을 수행하기 전 사용자의 확인을 거치도록 설계되었더라도, 자동 진행으로 인해 확인 절차를 우회하고 실제 시스템에 변경을 가할 수 있습니다. 예를 들어, 프로덕션 데이터베이스 수정, 중요한 서비스 배포, 대량의 리소스 생성 및 삭제 등이 사용자의 명시적인 승인 없이 진행될 수 있습니다.

### 2. 비용 폭주 (Runaway Costs)
클라우드 리소스 생성이나 API 호출과 같이 비용이 발생하는 작업에 대한 확인 절차가 누락될 경우, 에이전트가 무한 루프에 빠지거나 비효율적인 방식으로 작업을 반복하여 예상치 못한 비용이 발생할 수 있습니다.

### 3. 감사 및 추적의 어려움 (Auditability & Traceability Challenges)
자동 진행된 작업은 누가, 언제, 왜 해당 작업을 승인했는지에 대한 명확한 기록이 남지 않아, 문제 발생 시 원인 분석 및 책임 소재를 파악하기 어렵게 만듭니다. 이는 컴플라이언스 및 규제 준수 측면에서도 심각한 문제입니다.

### 4. 예측 불가능한 시스템 상태 (Unpredictable System State)
에이전트의 자율적인 판단에 따른 작업은 시스템의 상태를 예측 불가능하게 만들며, 다른 자동화 시스템이나 개발자의 기대와 어긋나는 결과를 초래할 수 있습니다. 이는 시스템의 전반적인 신뢰도를 저하시킵니다.

## 하네스 레벨의 가드레일 강화 전략

이러한 위험을 방지하기 위해 Claude Code 하네스 내에 명시적인 제어 및 가드레일을 구현하는 것이 필수적입니다. 핵심은 `AskUserQuestion` 호출 시, 자동 진행 여부를 명시적으로 제어하고, 기본값을 안전하게 설정하는 것입니다.

### 1. 명시적 `allow_auto_proceed_on_timeout` 설정
하네스 수준에서 `AskUserQuestion`과 같은 사용자 인터랙션 함수를 래핑(Wrap)하고, 자동 진행 여부를 명시적인 설정 (예: `allow_auto_proceed_on_timeout: false`)으로 제어해야 합니다. 기본값은 항상 `false`로 설정하여 사용자 개입이 없으면 대기하거나 오류를 발생시키도록 합니다.

### 2. 위험도 기반의 정책 적용
작업의 위험도에 따라 자동 진행 정책을 다르게 적용합니다. 예를 들어, `critical_action=True`로 플래그된 작업은 `allow_auto_proceed_on_timeout` 설정과 무관하게 무조건 사용자 개입을 요구하도록 설계할 수 있습니다.

### 3. 상세 로깅 및 모니터링
모든 `AskUserQuestion` 호출, 사용자 응답, 그리고 타임아웃 발생 및 자동 진행 결정을 상세하게 로깅합니다. 이를 통해 시스템 관리자는 에이전트의 자율적인 행동을 추적하고, 예상치 못한 동작을 즉시 감지할 수 있습니다.

### 4. 사용자 알림 및 에스컬레이션
타임아웃으로 인한 자동 진행이 발생할 경우, 관련 담당자에게 즉시 알림을 보내고 필요한 경우 에스컬레이션 절차를 따르도록 합니다. 이는 문제의 확산을 방지하고 신속한 대응을 가능하게 합니다.

### 예시 코드: 안전한 AskUserQuestion 래퍼

아래 Python 예시는 Claude Code 하네스에서 `AskUserQuestion` 호출을 래핑하여 명시적인 가드레일을 적용하는 방법을 보여줍니다. `UserInteractionGuard` 클래스는 자동 진행 여부와 타임아웃을 제어하고, `critical_action` 플래그를 통해 중요한 작업에 대한 안전 장치를 강화합니다.

```python
# claude_harness_guard.py
import time

class UserInteractionGuard:
    """
    Claude Code의 AskUserQuestion 자동 진행을 제어하는 가드레일 클래스.
    명시적인 설정을 통해 의도치 않은 자동 진행을 방지합니다.
    """
    def __init__(self, allow_auto_proceed_on_timeout: bool = False, timeout_seconds: int = 60):
        """
        :param allow_auto_proceed_on_timeout: 타임아웃 발생 시 자동 진행을 허용할지 여부. 기본값은 False (명시적 중단).
        :param timeout_seconds: 사용자 응답 대기 시간 (초).
        """
        self._allow_auto_proceed = allow_auto_proceed_on_timeout
        self._timeout = timeout_seconds
        print(f"UserInteractionGuard initialized: Auto-proceed on timeout: {self._allow_auto_proceed}, Timeout: {self._timeout}s")

    def ask_user_question_safe(self, question_prompt: str, critical_action: bool = False) -> str:
        """
        Claude Code의 AskUserQuestion을 안전하게 래핑하여 사용자 개입을 관리합니다.
        :param question_prompt: 사용자에게 제시할 질문.
        :param critical_action: 이 질문이 중요한 작업과 관련되어 있는지 여부.
                                True인 경우 allow_auto_proceed_on_timeout이 False여야 함.
        :return: 사용자 응답 또는 가드레일 결정에 따른 문자열.
        """
        print(f"Agent asks: '{question_prompt}'")
        print(f"Awaiting user input for {self._timeout} seconds...")

        effective_auto_proceed = self._allow_auto_proceed
        if critical_action and effective_auto_proceed:
            print("WARNING: Critical action requested, but auto-proceed is enabled. Overriding to 'False' for safety.")
            effective_auto_proceed = False

        # Simulate user input or timeout (in a real system, this would be an API call or UI interaction)
        user_response_received = False # For demonstration, assume no immediate response
        
        if user_response_received:
            response = "User provided explicit input." # Actual input would be captured here
            print(f"User responded: '{response}'")
        elif effective_auto_proceed:
            response = "[AUTO_PROCEED_DEFAULT]" # Agent proceeds with a pre-defined default action
            print(f"Timeout reached. Proceeding automatically as '{response}'.")
        else:
            response = "[HALT_AWAITING_HUMAN_INTERVENTION]" # Agent execution halts
            print(f"Timeout reached. Halting execution. Requires human intervention.")
        
        return response

# Example Usage:

```

## 트레이드오프

Claude Code 하네스의 자동 진행 기능에 가드레일을 강화하는 것은 시스템의 안전성과 예측 가능성을 높이지만, 특정 상황에서는 trade-off가 발생할 수 있습니다.

*   **생산성 vs. 안전성**: 자동 진행을 완전히 비활성화하거나 엄격한 제어를 가하면, 에이전트의 자율성과 작업 완료 속도가 저해될 수 있습니다.
    *   **언제 좋고**: 프로덕션 배포, 민감한 데이터 처리, 비용 발생 가능성이 있는 작업 등 높은 안정성과 통제가 필요한 시나리오에 적합합니다.
    *   **언제 나쁜지**: 개발/테스트 환경에서 빠른 프로토타이핑, 반복적인 문서 생성 등 낮은 위험도의 작업에서 지나친 개입은 불필요한 마찰을 유발하여 개발 속도를 늦춥니다.
*   **복잡성 vs. 명확성**: 명시적인 가드레일 로직을 구현하고 관리하는 것은 하네스 코드의 복잡성을 증가시킵니다. 에이전트와 하네스 간의 인터페이스도 더 정교해집니다.
    *   **언제 좋고**: 대규모 팀이 협업하거나, 규제 준수가 중요한 엔터프라이즈 환경에서 에이전트 동작의 명확성과 감사 가능성을 확보하는 데 필수적입니다.
    *   **언제 나쁜지**: 소규모 개인 프로젝트나 POC 단계에서는 오버헤드로 작용할 수 있으며, 개발 초기 단계의 빠른 실험을 방해할 수 있습니다.
*   **유연성 vs. 예측 가능성**: 에이전트의 유연한 문제 해결 능력은 자동 진행을 통해 강화될 수 있습니다. 가드레일은 이러한 유연성을 제한하고 예측 가능한 동작을 강제합니다.
    *   **언제 좋고**: 예측 가능한 결과가 중요한 시스템에서 예상치 못한 에이전트의 행동으로 인한 사이드 이펙트를 최소화할 수 있습니다.
    *   **언제 나쁜지**: 탐색적 코딩, 새로운 아이디어 발상 등 에이전트의 창의적이고 비정형적인 접근이 필요한 작업에서는 유연성을 해칠 수 있습니다.
*   **즉각성 vs. 검증**: 자동 진행은 즉각적인 작업 완료를 가능하게 하지만, 이는 검증 단계를 생략할 위험이 있습니다. 가드레일은 검증의 기회를 제공합니다.
    *   **언제 좋고**: 최종 사용자에게 영향을 미치거나 복구 비용이 큰 작업에 대해 오류 발생 가능성을 줄이고 품질을 보장합니다.
    *   **언제 나쁜지**: 실시간 응답이 필수적이거나, 실패의 영향이 미미하며 롤백이 쉬운 작업에서는 불필요한 지연을 초래할 수 있습니다.

## 실전 체크리스트

Claude Code 하네스에서 `AskUserQuestion` 자동 진행 기능에 대한 가드레일을 강화할 때 다음 항목들을 점검하세요.

- [ ] **`AskUserQuestion` 래핑 확인**: 모든 `AskUserQuestion` (또는 유사한 사용자 인터랙션) 호출이 커스텀 가드레일 함수(예: `ask_user_question_safe`)를 통해 이루어지는지 확인합니다.
- [ ] **기본 자동 진행 설정 검토**: 하네스 전반의 `allow_auto_proceed_on_timeout` 기본값이 `False`로 설정되어 있는지, 또는 프로덕션 환경에서 안전한 정책을 따르는지 확인합니다.
- [ ] **위험도별 정책 적용**: `critical_action` 플래그 또는 유사한 메커니즘을 사용하여 중요 작업에 대해서는 자동 진행을 강제로 비활성화하는 정책이 올바르게 구현되었는지 검증합니다.
- [ ] **로그 및 모니터링 시스템 연동**: 사용자 질문, 응답, 타임아웃, 자동 진행 결정 등 모든 인터랙션 이벤트가 상세히 로깅되고, 이상 감지 시 적절한 알림 (예: Slack, PagerDuty)이 발송되는지 확인합니다.
- [ ] **에이전트 역할 및 권한 재평가**: 자동 진행과 결합될 수 있는 에이전트의 도구 사용 권한 (Tool Use Permissions)이 최소 권한 원칙 (Principle of Least Privilege)에 따라 필요한 범위로 제한되어 있는지 정기적으로 검토합니다.
- [ ] **비상 정지 (Emergency Stop) 메커니즘**: 에이전트가 통제 불능 상태에 빠질 경우 즉시 모든 작업을 중지시킬 수 있는 비상 정지 메커니즘이 존재하고, 작동 가능성을 주기적으로 테스트하는지 확인합니다.
- [ ] **변경 로그 및 문서화 업데이트**: 하네스의 가드레일 정책 및 `AskUserQuestion` 동작 방식에 대한 변경 사항이 내부 변경 로그와 기술 문서에 명확하게 기록되어 팀원들이 최신 정보를 공유하는지 확인합니다.
