LLM (Large Language Model) 기반 애플리케이션의 개발 및 운영은 전통적인 소프트웨어 개발과는 다른 복잡성을 내포합니다. 모델의 비결정성(non-determinism), 데이터 및 모델 드리프트(drift), 프롬프트 엔지니어링의 동적인 특성 등으로 인해 안정적이고 효율적인 CI/CD (Continuous Integration/Continuous Deployment) 워크플로우 설계는 필수적입니다. 이 엔트리는 LLM 애플리케이션의 고유한 요구사항을 반영한 CI/CD 워크플로우 설계 방법을 다룹니다.

## LLM CI/CD의 핵심 과제

LLM 애플리케이션은 모델 자체의 변경 외에도 학습 데이터, 프롬프트, 외부 도구(tool) 연동 등 다양한 요소가 복합적으로 작용하여 품질과 성능에 영향을 미칩니다. 이러한 특성 때문에 다음과 같은 핵심 과제들을 해결해야 합니다.

### 데이터 드리프트 (Data Drift)
LLM의 성능은 학습 및 추론에 사용되는 데이터의 분포에 크게 의존합니다. 실제 서비스 환경에서 사용자 입력 데이터의 분포가 학습 데이터와 달라지면(데이터 드리프트) 모델 성능이 저하될 수 있습니다. 단순한 스키마 변경을 넘어, 사용자 질문의 의도나 사용되는 어휘의 변화와 같은 의미론적(semantic) 드리프트까지 감지하고 관리해야 합니다.

### 모델 드리프트 (Model Drift)
LLM 제공사(예: OpenAI, Anthropic)의 모델 업데이트, 자체 fine-tuning 모델의 재학습 등으로 인해 모델의 출력 패턴이 예기치 않게 변경될 수 있습니다. 이는 프롬프트와 애플리케이션 로직이 기대하는 모델 동작과 달라지는 결과를 초래할 수 있습니다. 이러한 미묘한 동작 변화를 지속적으로 감지하고 평가하는 것이 중요합니다.

### 프롬프트 버전 관리 및 테스트 (Prompt Versioning & Testing)
프롬프트는 LLM 애플리케이션의 핵심 로직이자 '코드'입니다. 프롬프트의 미세한 변경도 애플리케이션의 동작과 출력 품질에 큰 영향을 미치므로, 일반 코드처럼 엄격한 버전 관리, 리뷰, 그리고 자동화된 테스트가 필요합니다. 단순한 텍스트 변경을 넘어, 프롬프트 템플릿, Few-shot 예제, 시스템 메시지 등 모든 구성 요소를 관리해야 합니다.

### 복합적인 평가 및 검증 (Complex Evaluation & Validation)
LLM의 출력은 정답이 명확하지 않은 경우가 많아, 전통적인 단위 테스트(unit test)만으로는 품질을 담보하기 어렵습니다. ROUGE, BLEU와 같은 자연어 처리(NLP) 지표는 한계가 있으며, 안전성(safety), 편향(bias), 일관성, 유용성 등 다차원적인 평가가 요구됩니다. 자동화된 평가와 함께 사람의 개입(Human-in-the-Loop, HITL)을 통한 정성적(qualitative) 평가가 필수적입니다.

## LLM CI/CD 워크플로우 설계

LLM CI/CD 워크플로우는 데이터, 모델, 프롬프트, 그리고 애플리케이션 코드의 생명주기를 모두 통합하여 관리해야 합니다.

### 1. 데이터 파이프라인 (Data CI)
*   **데이터 유효성 검사**: 입력 데이터의 스키마, 분포, 품질을 지속적으로 검사하여 데이터 드리프트를 조기에 감지합니다. CTDS (Continuous Testing for Data Systems) 원칙을 적용합니다.
*   **데이터 버전 관리**: 학습 및 평가에 사용되는 모든 데이터를 DVC (Data Version Control) 또는 Delta Lake와 같은 도구를 활용하여 버전 관리하고 재현 가능성(reproducibility)을 확보합니다.
*   **전처리 자동화**: 데이터 전처리 스크립트도 코드처럼 관리하고, CI 파이프라인에서 자동 실행하여 일관성을 유지합니다.

### 2. 모델 파이프라인 (Model CI)
*   **자동 재학습 트리거**: 데이터 드리프트 감지, 성능 저하 감지, 새로운 데이터 유입 시 모델의 자동 재학습(re-training)을 트리거합니다.
*   **모델 버전 관리**: 학습된 모델 아티팩트(artifact)를 MLflow, BentoML 등 모델 레지스트리(Model Registry)에 등록하고 버전 관리합니다. 각 모델 버전별 메타데이터(학습 데이터, 하이퍼파라미터, 성능 지표)를 기록합니다.
*   **성능 벤치마킹**: 새로운 모델이 기존 모델 대비 성능 향상이 있는지 지속적으로 벤치마킹하고 검증합니다.

### 3. 프롬프트 파이프라인 (Prompt CI)
*   **프롬프트 버전 관리**: 프롬프트 텍스트, 템플릿(Jinja), Few-shot 예제, 시스템 메시지 등 모든 프롬프트 관련 자산을 Git과 같은 VCS (Version Control System)에 저장하고 버전 관리합니다.
*   **자동화된 프롬프트 테스트**: 정의된 '골든 데이터셋(Golden Dataset)'에 대해 프롬프트가 예상하는 출력을 생성하는지 자동화된 테스트를 수행합니다. 단순 일치 검사 외에 의미론적 유사성(semantic similarity), 특정 키워드 포함 여부, 출력 형식 준수 여부 등을 검사합니다.
*   **LLM-as-a-Judge**: 다른 LLM을 사용하여 프롬프트의 출력 품질을 평가하는 방식을 도입할 수 있으나, 평가 LLM 자체의 편향(bias)과 비용에 주의해야 합니다.

**Python을 이용한 프롬프트 테스트 예제:**
```python
# test_prompt.py
import pytest

# 실제 애플리케이션 코드의 프롬프트 생성 함수라고 가정
def generate_summary_prompt(text: str) -> str:
    return f"""Please summarize the following text concisely and accurately. Focus on key information only.

Input Text:
---
{text}
---

Summary:
"""

# CI 환경에서 사용할 mock LLM 응답 함수
def mock_llm_api_call(prompt: str) -> str:
    if "summarize" in prompt.lower() and "Input Text:" in prompt:
        # 간단한 요약 로직 시뮬레이션
        input_start = prompt.find("Input Text:") + len("Input Text:")
        input_end = prompt.find("---\n\nSummary:")
        input_text = prompt[input_start:input_end].strip().strip('---')
        
        words = input_text.split()
        summary_words = words[:min(15, len(words))]
        return f"A concise summary: {' '.join(summary_words)}..."
    return "[MOCK] Unexpected prompt structure."

def test_summary_prompt_generates_concise_output():
    """요약 프롬프트가 간결한 요약을 생성하는지 검증합니다."""
    long_text = (
        "Large Language Models (LLMs) have revolutionized natural language processing, "
        "enabling applications like chatbots, content generation, and code assistance. "
        "However, deploying LLMs in production requires robust MLOps practices, "
        "including continuous integration and continuous deployment pipelines. "
        "Key challenges involve managing data drift, model drift, and prompt versioning, "
        "alongside comprehensive evaluation strategies including automated metrics and human feedback. "
        "Effective CI/CD ensures that LLM-powered applications remain reliable, performant, and cost-efficient over time." 
    )
    prompt = generate_summary_prompt(long_text)
    response = mock_llm_api_call(prompt)
    
    assert "summary" in response.lower()
    assert "concise summary" in response.lower()
    assert len(response.split()) < len(long_text.split()) # 요약은 원문보다 짧아야 함
    assert "LLMs" in response # 핵심 키워드 포함 확인

def test_summary_prompt_structure_integrity():
    """요약 프롬프트의 구조적 무결성을 검증합니다."""
    text = "A short example text."
    prompt = generate_summary_prompt(text)
    assert "summarize" in prompt.lower()
    assert "input text:" in prompt.lower()
    assert "summary:" in prompt.lower()
    assert text in prompt
```

### 4. 애플리케이션 코드 CI/CD
*   **표준 CI/CD 프로세스**: LLM 연동 로직, RAG (Retrieval Augmented Generation) 파이프라인, 외부 도구(tool) 연동 코드 등은 일반적인 소프트웨어 개발의 CI/CD best practice를 따릅니다. 단위 테스트, 통합 테스트, 코드 정적 분석 등을 수행합니다.
*   **종속성 관리**: LLM SDK, 벡터 데이터베이스 클라이언트 등 LLM 관련 라이브러리 종속성(dependency)을 안정적으로 관리합니다.

### 5. 배포 및 오케스트레이션 (Deployment & Orchestration)
*   **점진적 배포 (Progressive Delivery)**: 카나리(canary) 배포, 블루-그린(blue-green) 배포 전략을 활용하여 새로운 모델이나 프롬프트 변경 사항을 소수의 사용자에게 먼저 노출하고, 문제가 없을 경우 점진적으로 전체 사용자에게 확대합니다.
*   **A/B 테스팅**: 여러 모델 버전 또는 프롬프트 전략을 동시에 운영하고, 사용자 지표(engagement, conversion)를 기반으로 최적의 버전을 결정합니다.
*   **지능형 라우팅 (Intelligent Routing)**: 모델 게이트웨이(gateway)를 활용하여 사용자 요청을 적절한 LLM 엔드포인트(endpoint)로 라우팅하고, 폴백(fallback) 전략을 구현하여 안정성을 높입니다.

### 6. 모니터링 및 피드백 루프 (Monitoring & Feedback Loop)
*   **실시간 모니터링**: LLM 서비스의 지연 시간(latency), 처리량(throughput), 토큰 사용량, 비용, 오류율 등의 운영 지표를 실시간으로 모니터링합니다. OpenTelemetry와 같은 표준을 활용하여 분산 트레이싱(distributed tracing)을 구현합니다.
*   **품질 지표 모니터링**: LLM 출력의 품질(정확도, 관련성, 안전성)을 나타내는 지표를 정의하고, 일정 임계치(threshold)를 벗어날 경우 자동으로 알림을 발생시킵니다.
*   **드리프트 감지**: 데이터 드리프트 및 모델 드리프트를 감지하는 시스템을 구축하고, 이상 감지 시 모델 재학습 또는 프롬프트 조정 파이프라인을 자동 트리거합니다.
*   **사용자 피드백 통합**: 사용자 불만, 부정확한 응답 등 실제 사용자 피드백을 수집하고, 이를 평가 데이터셋 개선 및 모델/프롬프트 최적화에 활용하는 피드백 루프를 구축합니다.
