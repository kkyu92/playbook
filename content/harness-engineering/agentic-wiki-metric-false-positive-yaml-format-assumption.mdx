## MDX frontmatter 두 가지 connections 형식

플레이북 wiki에 두 가지 connections 표기 방식이 병존:

```yaml
# 형식 A — YAML list (수동 큐레이션 entries)
connections:
  - harness-engineering/drift-detection-methodology
  - harness-engineering/agentic-context-compaction-commit-density-survival
```

```yaml
# 형식 B — Array (gap-pull/scout 자동 생성 entries)
connections: [prompt-engineering/llm-prompt-optimization-role-definition-constraint-design, data-engineering/llm-fine-tuning-dataset-preparation-strategies, ...]
```

**발생 경위**: harness-engineering curated entries = YAML list format. gap-pull/scout batch entries = array format. 두 형식이 동일 wiki 안에 혼재.

```python
# ✅ 수정 버전 — 양쪽 형식 모두 처리
# YAML list
m = re.search(r'connections:\s*\n((?:[ \t]+-[ \t]+.+\n?)*)', content)
if m:
    items = [i.strip() for i in re.findall(r'-\s*(.+)', m.group(1)) if len(i.strip()) > 3]
    conn_count = len(items)
# Array format
m2 = re.search(r'connections:\s*\[([^\]]+)\]', content)
if m2:
    items = [i.strip() for i in m2.group(1).split(',') if i.strip()]
    conn_count = len(items)
```

## 탐지 패턴

### Wiki health script 작성 시 format 검증 체크리스트

- [ ] 측정 대상 필드의 모든 YAML 표기 형식 파악 (list / array / 멀티라인 block scalar `>-`)
- [ ] 각 형식별로 샘플 entry 3개 이상 수동 검증
- [ ] 전체 count가 총 entry 수와 일치하는지 확인 (누락 = 미인식 format 존재)
- [ ] `total_with_field > 0 && total_with_field < total_entries` 이면 format 파싱 버그 의심

### 빠른 format 분포 확인

```bash
# connections: 형식 분포 확인
grep -r "^connections:" content/ --include="*.mdx" | head -3  # array format
grep -r "^connections:$" content/ --include="*.mdx" | head -3  # list format  
grep -r "^connections: \[" content/ --include="*.mdx" | wc -l  # array count
grep -r "^connections:$" content/ --include="*.mdx" | wc -l   # list count
```

## 관련 측정 artifact

**YAML block scalar `>-`**: `closed-loop-health.mdx` connections 내 긴 slug를 `>-` 멀티라인으로 박제 → 스크립트가 `>-` 를 연결 대상으로 오인식.

```yaml
connections:
  - >-
    harness-engineering/frontend-ai-response-safety-net-validation-adaptation-feedback-loop
```

orphan 스캔 시 `>-` 자체가 orphan target으로 보고됨 (실제 orphan X). 위 수정 스크립트에서 `len(i.strip()) > 3` 가드가 필요한 이유.
