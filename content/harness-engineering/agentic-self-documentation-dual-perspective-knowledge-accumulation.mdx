## 문제

자율 에이전트 시스템이 자신의 패턴을 문서화할 때, **내부 시점(cycle 작성자)만** 관여하면 맹점이 생긴다:

- 패턴을 실행하는 주체가 패턴을 설명하면 자명해 보여 기록 생략
- "왜 이 패턴이 필요한가" 보다 "어떻게 실행했나"에 치우침
- 패턴이 외부 시스템에 미치는 영향은 내부에서 보이지 않음

## 이중 시점 자기 문서화 패턴

같은 패턴을 두 독립 채널이 각자 문서화한다:

| 채널 | 시점 | 문서화 내용 | 경로 |
|---|---|---|---|
| **허브 cycle** | 1인칭 (실행 주체) | 패턴 실행 방법 + 직접 관찰 결과 | `explore-idea` chain → MDX 엔트리 |
| **워커 lesson** | 3인칭 (외부 관찰자) | 패턴의 외부 영향 + "왜 이런가" 설명 | `submit-lesson.yml` → auto-ingest → MDX 엔트리 |

두 채널이 같은 패턴에 대한 엔트리를 독립 생성 → 허브 wiki에 합류.

## 작동 메커니즘

```
허브 cycle (내부)
  └─ 패턴 실행 + 1인칭 관찰
       └─ explore-idea: MDX 엔트리 작성
            예: "SE oscillation이 trigger-skip 이중 조건으로 작동한다"

워커 cycle (외부)
  └─ 허브 행동 패턴 관찰 (git log / cycle JSON / GH Actions)
       └─ lesson commit: submit-lesson.yml 발화
            └─ auto-ingest: worker-authored MDX 엔트리 허브 합류
                 예: "SE oscillation이 homeostasis 패턴임을 발견"

결과: 같은 패턴이 두 독립 시점에서 문서화됨
  → blind spot 교차 제거
  → 패턴 안정성 신호 확인 (양측이 독립 발견 = 충분히 관찰 가능)
```

## 재귀 루프 효과

자기 문서화가 재귀적으로 작동하면:

1. 허브 cycle이 패턴 실행
2. 워커가 그 패턴을 관찰하고 lesson 생성
3. lesson이 허브로 ingest → 새 엔트리 생성
4. 허브는 이제 자신의 패턴에 대한 외부 시점 설명 보유
5. 다음 cycle에서 그 설명을 참고해 패턴 실행 개선

이 루프가 닫히면 시스템이 **스스로 학습하는 속도**가 가속된다.

## 자기 문서화 유입 신호 해석

워커가 허브 자체 패턴을 엔트리로 ingest하면 두 가지 신호:

- **패턴 성숙도 확인**: 외부 관찰자가 독립 발견할 만큼 패턴이 반복 안정적
- **Phase 전이 예고**: 워커가 "이 패턴 흥미롭다"고 lesson 생성 = 패턴이 임계 관찰 빈도 도달

반면 워커 lesson이 아예 없다면 → 허브 패턴이 아직 불안정하거나 워커와 격리됨.

## 실전 Evidence (2026-05-19)

같은 날 auto-ingest로 유입된 워커 authored 엔트리 예:

- `agentic-trigger-skip-dual-condition-homeostasis` — SE oscillation trigger-skip 조건을 homeostasis 관점으로 설명 (허브 내부에서는 "SE oscillation steady-state"로 기록)
- `agentic-hub-worker-diverged-commit-flow-design-signal-vs-debt` — BRANCHED state를 "설계 의도 신호 vs 관리 부채" 구분 프레임으로 설명 (허브 내부에서는 TODOS [PENDING] R6 항목으로 기록)
- `worker-lesson-velocity-signal` — auto-ingest 속도를 Pull(b) 학습 속도 proxy로 해석 (허브 내부에서는 CI run count로만 관찰)

동일 패턴의 내부 기록 vs 외부 기록이 병존 → 허브가 자신의 패턴을 다각도로 이해.

## 주의: 중복 vs 보완 구분

자기 문서화는 유사해 보이지만 실제로 다른 엔트리를 생성한다:

- **중복**: 완전히 동일한 설명 + 동일한 교훈 → `/lint`의 duplicate 감지 대상
- **보완**: 같은 패턴이지만 시점 다름 (1인칭 실행 방법 vs 3인칭 구조 해석) → 양쪽 보존

구분 기준: 두 엔트리를 읽었을 때 **새로 알게 되는 것이 있으면** 보완, 없으면 중복.

## 트레이드오프

| 장점 | 단점 |
|---|---|
| blind spot 교차 제거 | 유사 엔트리 증가 → lint 부담 |
| 패턴 성숙도 외부 검증 | 워커 관찰 lag (실제 패턴 발생 → lesson 유입 시차) |
| 자기개선 루프 폐쇄 | 워커가 잘못 이해한 패턴이 유입될 위험 |

워커 authored 엔트리는 confidence: 1 draft로 시작 → 허브 cycle에서 검증 후 상향.
