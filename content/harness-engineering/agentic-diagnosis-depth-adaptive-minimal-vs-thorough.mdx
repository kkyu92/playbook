## 진단 깊이 스펙트럼

```
최소 스캔 (30초):     gh issue list → 있으면 즉시 chain 선택
표준 스캔 (2-3분):    issues + plans + lint:wiki + TODOS 훑기
심층 스캔 (5-10분):   전체 source + gh run list + scan-promotions + git log
```

## 깊이 결정 기준

| 조건 | 권장 깊이 | 이유 |
|---|---|---|
| open issues ≥ 10건 | 최소 | 명확한 chain 선택 — 추가 스캔 불필요 |
| open issues = 0 + next_recommended 신뢰 | 표준 | 추천 힌트 있으면 심층 불필요 |
| 배치 첫 번째 사이클 | 심층 | 직전 세션 이후 누적 변화 파악 필요 |
| 배치 마지막 1-2 사이클 | 표준 | 정리 작업, 심층 새 발견 불필요 |
| 이전 사이클 fail | 심층 | 실패 원인 탐색 필요 |
| 이전 사이클 success (stable 패턴) | 최소-표준 | 안정적 패턴 유지 |

## 배치 위치별 권장 깊이

```
사이클 1-3 (배치 시작):    심층 (누적 파악)
사이클 4-N-3 (중간):       표준 (패턴 유지)
사이클 N-2 ~ N (마지막):   표준 (close-out)
```

## 과잉 진단 비용

심층 스캔을 매 사이클 실행 시:
- context 소비 증가 (git log 20 + lint:wiki output + gh run list)
- 실제 chain 작업 시간 감소
- 발견 대비 효용 감소 (stable phase에서 새 발견 희박)

rule: **진단 output이 chain 선택을 바꿀 가능성이 낮으면 shallow 스캔으로 전환**.
