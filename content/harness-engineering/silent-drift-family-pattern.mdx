## 문제

자동화 루프에서 가장 비싼 결손은 [작동 드리프트 #3](/wiki/harness-engineering/drift-detection-methodology) 의 sub-family — `try { ... } catch {}` empty catch, `.error` 미체크, fallback 0 stub, JSON.parse 미가드 — 이 모두 **silent 하게 실패**해서 자동화 루프 안에서 "성공"으로 박제된다. CI green / cron success / lint pass 모두 통과해도 결과만 invisible degradation.

이 패턴은 워커 (머니볼) 에서 23 cycle SUCCESS streak 으로 먼저 정착됐고, 허브 (playbook) 에 cross-project transport 되어 13 fork 누적했다. 9 fork 후 scripts/ 영역에서 자연 종료 신호를 detect 했고 (cycle 70), 그 직후 cycle 78 에서 src/lib 첫 직교 진입 → cycle 80 N=2 deepen (quiz-storage + auth.ts) → cycle 82 src/app + components 차원 직교 두 번째 누적 → **cycle 84 scripts/ 차원 재진입 (watch-content + search 잔여 가시화) — 차원 직교 fork 회귀 패턴 첫 evidence**. 본 entry 의 [차원 재정의 trigger #1](#차원-재정의-trigger) 자연 발화 N=3 dogfood + 강한·약한 의도 보존 분류 첫 동시 적용 + cycle 79 entry 박제 명제 "scripts/ 자연 종료" 의 cycle 84 reverse 약한 결론 N=1 메타 lens 자연 추가.

## chain dominance 자연 정착 — review-code lite/heavy

13 fork 중 **12건이 review-code chain** (lite 10 + heavy 2) → 직전 25 cycle 중 review-code dominant 패턴 자연 정착. 직전 6 cycle (79~84) chain distribution:

- 79: explore-idea (lite) — 본 entry 박제 (10 fork 시점)
- 80: review-code (lite) ⭐⭐ src/lib N=2 deepen
- 81: curate — dispatch 채널 80 cycle 누적 균형 분석
- 82: review-code (lite) ⭐⭐⭐ src/app + components 두 번째 직교
- 83: explore-idea (lite) — 본 entry 12 fork 시점 갱신 + 보존 판정 reverse 메타 lens 자연 추가
- 84: review-code (lite) ⭐⭐⭐⭐ scripts/ 재진입 (회귀 패턴 첫 evidence)

`R3 회피` (직전 3 사이클 모두 같은 chain X) 룰이 review-code 의 외부 source trigger 에 자연 응답 — silent drift 발견 시 review-code 진입, 다른 외부 source (curate / explore-idea / skill-evolution / closed-loop-design) 도 자연 끼워 dominance 자체가 정합. cycle 79 explore-idea + 81 curate + 83 explore-idea 가 review-code dominance 사이 자연 분산.

**메타 lens 정착**: 일회성 의도 분류는 시간 lens 따라 reverse 가능. 분류 기준 cycle 84 첫 동시 적용:

- **강한 보존** (보안/안전 critical, cleanup/dev-only, **자식 process 가 직접 stderr 출력 → 부모 catch silent 이중 출력 회피**, `} catch { /* already exists */ }` 같은 강한 의도 주석 명시) — cycle 70~84 14 사이클 동안 0건 reverse 정합. 영구 정합
- **약한 보존** (의도 명시 가능하지만 한 줄 주석 / 단일 site 분류 / debugging path 정보 surface 가치 ↑) — 추후 재진입 시 reverse 가능. cycle 80~84 사이 9건 reverse evidence

[question-own-defaults](/wiki/harness-engineering/question-own-defaults) 정합: "의도 명시 분류" 자체도 자가 의심 대상 — 첫 grep 단일 site 만 본 결정은 동 파일 안 추가 catch 누락 가능. 강한 보존 (보안 critical / cleanup / dev-only / 자식 process 직접 출력) 외 약한 보존은 추후 재진입 시 reverse trigger.

**자가 dogfood**: cycle 78 분류 vs cycle 80~82 reverse 가 본 entry 안 박제 → cycle 84 강한·약한 보존 동시 적용 = entry 자체가 보존 분류 reverse 패턴을 박제하는 메커니즘 작동 N=2 evidence.

## 자연 종료 신호 detect — cycle 70 명제와 cycle 84 reverse (약한 결론 N=1)

cycle 70 진단 시 scripts/ 잔여 silent catch 5건 모두 **의도적 silent** 로 판정 → 자연 종료 detect. 그러나 cycle 84 진단 시 scripts/ 재진입 시 **2건 가시화 가능** 으로 reverse:

| 위치 | cycle 70 분류 | cycle 84 처리 | 사유 |
|---|---|---|---|
| `scout-geeknews.mjs:211` | 의도 (`already exists`) | **보존 유지** | 강한 보존 정합 (14 사이클 reverse 0) |
| `scout-geeknews.mjs:228` | 의도 (cleanup) | **보존 유지** | 강한 보존 정합 |
| `watch-content.mjs:26` | 의도 (dev tool watcher) | **보존 유지** | 강한 보존 — 자식 process 가 직접 stderr 출력 → 부모 catch silent OK (이중 출력 회피) |
| `watch-content.mjs:12` | 의도 (dev tool watcher) | **가시화** | 약한 보존 reverse — initial manifest gen 실패 reason surface 가치 ↑ |
| `search.mjs:41` | 의도 (주석 명시) | **가시화** | 약한 보존 reverse — HITS_FILE corruption reason + path surface 가치 ↑ |

**약한 결론 패턴 N=1 메타 lens** (entry 박제 명제 자체의 reverse 차원 — 보존 판정 reverse 와 직교):

- cycle 70 박제 명제 = "scripts/ 잔여 5건 모두 의도적 silent → 자연 종료"
- cycle 79 entry 박제 = "scripts/ 자연 종료 detect 의 의미"
- **cycle 84 reverse**: 5건 중 2건 가시화 가능 발견 → entry 박제 명제 일부 reverse

**보존 판정 reverse 와 약한 결론 reverse 의 차이**:

- 보존 판정 reverse = 단일 catch site 의 분류 reverse (cycle 78 → 80 사이 동 파일 추가 catch 발견)
- 약한 결론 reverse = entry 박제 **명제 자체** 의 reverse (cycle 70 "자연 종료" 명제 → cycle 84 부분 reverse)
- 두 lens 직교: 보존 reverse 는 site-level, 약한 결론 reverse 는 statement-level

**N=1 evidence**: cycle 84 = 첫 사례. N>=3 누적 시 entry 메타 lens 추가 후보 (entry 박제 명제 자체의 reverse 가 새 차원 trigger #5).

추가 grep (cycle 84 시점):

- scripts/ 잔여 약한 보존 0건 (watch-content:26 / scout-geeknews 2 = 강한 보존만)
- src/ 잔여 약한 보존 grep — 추후 재진입 가능 후보 (cycle 78 시점 분류 미검토 추가 영역 — code-block.tsx + api/og/route.tsx 잔여 부분 보존)

**자연 종료 detect 의 재해석**: cycle 70 의 "scripts/ 자연 종료" 는 영구 X — 시간 lens (14 사이클) 따라 약한 보존 영역 reverse 가능. 자연 종료 = "현 시점 산술 종료", 재진입 = "lens 변경 시 재발견". chain 자연 dormant 와 차원 회귀 양립.

**메타 패턴 N=3 evidence**:

1. 자연 종료 detect 후 강제 새 도메인 진입 X — scripts/ 종료 후 8 사이클 자연 source 발화 (curate / skill-evolution / closed-loop-design / explore-idea) 끼워 R3 정합 후 src/lib 자연 진입

3. **src/app+components 종료 후 1 사이클 (cycle 83 explore-idea 끼움) → scripts/ 차원 재진입 자연 발화 = 차원 직교 fork 회귀 패턴 첫 evidence** (종료된 차원 다시 진입 = "자연 종료" 가 영구 종료 X 명시)

## 메타 lens — 머니볼 23 streak → 허브 13 fork (도메인 직교 + 회귀 진입) transport

본 패턴은 워커 (머니볼) 의 23 cycle SUCCESS streak 정착 후 cross-project transport 됐다:

- 머니볼 cycle 100~123: silent drift family 23 fork (`assertSelectOk` helper 통일 + `.error` 가시화) — packages/kbo-data + apps/moneyball page + lib/dashboard + route handler 4+ 차원
- 허브 cycle 54~84: 13 fork transport 누적 — scripts/ 9 fork 자연 종료 (cycle 70) + src/lib 3 fork (cycle 78 첫 진입 + cycle 80 N=2 deepen) + src/app+components 직교 두 번째 fork (cycle 82) + **scripts/ 회귀 13번째 fork (cycle 84 = 차원 재진입 첫 evidence)** 차원 직교 N=2 + 회귀 N=1 누적

머니볼 패턴은 codebase 큰 만큼 동일 helper 패턴 다차원 재진입, 허브는 codebase 작아 scripts/ 단일 차원 자연 종료 후 src/ 영역도 lib → app+components 차원 직교 두 단계로 진입, 그 후 scripts/ 회귀로 4 도메인 cycle 회귀. **허브 fork 패턴 = "차원 종료 → 직교 도메인 진입 N=2 → 종료 차원 회귀 진입" N=3 단계 evidence** (cycle 78 → 82 → 84 자연 진행, 머니볼 동차원 재진입 패턴과 직교 + 회귀 동시).

[hub-worker-compounding-pattern](/wiki/harness-engineering/hub-worker-compounding-pattern) 의 양방향 흐름 dogfood evidence: 워커 → 허브 transport (PR auto-tag + auto-ingest 채널) 가 패턴 자체를 흘려보냈고, 허브는 자체 코드 baseline 따라 도메인 직교 + 회귀 fork 패턴으로 진화.

## 차원 재정의 trigger

본 entry 박제 후 silent drift family chain 자연 추가 발화 조건:

1. **✅ N=3 cycle 71+ 에서 새 영역 발견** — cycle 78 src/lib 첫 진입 + cycle 82 src/app + components 차원 직교 두 번째 + **cycle 84 scripts/ 차원 회귀 (N=3 evidence)**. 추가 자연 등장 영역 후보 = content/ MDX 위키 / GitHub Actions yaml shell embed (R6) / Cloudflare worker TypeScript (R6) / src/app + components 잔여 약한 보존 (보존 reverse 가능)
2. **머니볼 fork 추가 transport** — 머니볼 cycle 165+ 가 silent drift family 새 차원 (예: api route handler / sync job concurrency / migration safety / write 측 assertWriteOk) 발견 시 cross-project 자연 transport
3. **chain dominance 다른 패턴 정착** — review-code 외 chain (closed-loop-design 등) 이 silent fail 가시화 영역에 자연 발화 시 메타 lens 보강. 직전 6 cycle (79~84) 에서 explore-idea (79, 83) + curate (81) 끼워 review-code dominance 균형 (R3 회피 정합)
4. **✅ 보존 판정 reverse (시간 lens)** — cycle 78 분류 vs cycle 80~82 reverse + cycle 84 강한·약한 분류 동시 적용 evidence. 강한 보존 (보안/cleanup/dev-only/자식 process 직접 출력) vs 약한 보존 (의도 명시 가능, 한 줄 주석, 단일 site 분류) 자연 구분 N=2 dogfood
5. **약한 결론 reverse (entry 박제 명제 lens)** — cycle 79 entry 박제 명제 "scripts/ 자연 종료" 의 cycle 84 부분 reverse N=1 evidence. N>=3 누적 시 entry 메타 lens 추가 후보 (entry 박제 명제 자체의 reverse 차원, 보존 판정 reverse 와 직교)

**차원 재정의 X 시 동작**: silent drift family chain trigger 자체 자연 dormant — 외부 source 부재 → review-code 자체 자연 종료 (cycle 70 dimension-cycle RETRO-ONLY 정합). 본 entry 가 "dormant 도 정합" evidence 박제. cycle 84 dogfood 후 src/ 잔여 약한 보존 catch 도 추후 재진입 시 reverse 가능 — 자연 종료 detect 세 번째 단계 + 보존 reverse N=3 가능.
