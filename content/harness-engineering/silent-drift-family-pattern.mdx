## 문제

자동화 루프에서 가장 비싼 결손은 [작동 드리프트 #3](/wiki/harness-engineering/drift-detection-methodology) 의 sub-family — `try { ... } catch {}` empty catch, `.error` 미체크, fallback 0 stub, JSON.parse 미가드 — 이 모두 **silent 하게 실패**해서 자동화 루프 안에서 "성공"으로 박제된다. CI green / cron success / lint pass 모두 통과해도 결과만 invisible degradation.

이 패턴은 워커 (머니볼) 에서 23 cycle SUCCESS streak 으로 먼저 정착됐고, 허브 (playbook) 에 cross-project transport 되어 10 fork 누적했다. 9 fork 후 scripts/ 영역에서 자연 종료 신호를 detect 했고, 그 직후 cycle 78 에서 src/ 새 도메인 (Next.js 코드 영역) 으로 자연 직교 fork — 본 entry 의 [차원 재정의 trigger #1](#차원-재정의-trigger) 자연 발화 dogfood.

⭐ = scripts/ 자연 종료 (cycle 70) 후 src/ 새 도메인 첫 직교 fork — 차원 재정의 trigger #1 자연 발화.

각 fork = 1 commit 박제 (`fix(scripts):` 또는 `fix(src):`) + 1 retro commit (`policy: cycle N retro`). 10 fork 모두 outcome=success, R3 회피 정합 (5 review-code 연속 후 다른 chain 1회 이상 끼워 자연 분산).

## chain dominance 자연 정착 — review-code lite/heavy

10 fork 중 **9건이 review-code chain** (lite 7 + heavy 2) → 직전 20 cycle 중 review-code dominant 패턴 자연 정착. 직전 5 cycle (74~78) chain distribution:

- 74: closed-loop-design
- 75: curate
- 76: skill-evolution (trigger 5 N=2 dogfood)
- 77: curate
- 78: review-code (lite) ⭐ src/ 첫 진입

`R3 회피` (직전 3 사이클 모두 같은 chain X) 룰이 review-code 의 외부 source trigger 에 자연 응답 — silent drift 발견 시 review-code 진입, 다른 외부 source (curate / fix-incident / skill-evolution / closed-loop-design) 도 자연 끼워 dominance 자체가 정합.

## 메타 lens — 머니볼 23 streak → 허브 10 fork (도메인 직교 진입) transport

본 패턴은 워커 (머니볼) 의 23 cycle SUCCESS streak 정착 후 cross-project transport 됐다:

- 머니볼 cycle 100~123: silent drift family 23 fork (`assertSelectOk` helper 통일 + `.error` 가시화) — packages/kbo-data + apps/moneyball page + lib/dashboard + route handler 4+ 차원
- 허브 cycle 54~78: 10 fork transport 누적 — scripts/ 9 fork 자연 종료 + src/lib 첫 진입 (도메인 직교 fork) 1건

머니볼 패턴은 codebase 큰 만큼 동일 helper 패턴 다차원 재진입, 허브는 codebase 작아 scripts/ 단일 차원 자연 종료 후 코드 베이스 두 번째 차원 (src/ Next.js 영역) 으로 직교 진입. **허브 fork 패턴 = "차원 종료 → 직교 도메인 진입" 두 단계 evidence** (머니볼 동차원 재진입 패턴과 직교).

[hub-worker-compounding-pattern](/wiki/harness-engineering/hub-worker-compounding-pattern) 의 양방향 흐름 dogfood evidence: 워커 → 허브 transport (PR auto-tag + auto-ingest 채널) 가 패턴 자체를 흘려보냈고, 허브는 자체 코드 baseline 따라 도메인 직교 fork 패턴으로 진화.

## 박제 가치 — 무한 카운팅 X, 자연 종료 + 도메인 직교 fork 자체가 milestone

전통적 milestone 박제 default = "10 streak 도달 시 박제". 본 entry 는 그 default 를 깨뜨린다:

- **9 fork + 자연 종료 detect (cycle 70) + 도메인 직교 fork 1건 (cycle 78) = 충분 evidence**
- 10+ 산술 무한 누적 강박 X — chain 자체의 fix domain exhaustion 후 강제 trigger 발화하면 silent drift family 차원 외 발견을 silent drift 로 잘못 분류 risk
- chain dominance + 자연 종료 detect + 도메인 직교 진입 자체가 메타 패턴 차원
- **본 entry 자체 dogfood**: cycle 71 박제 → cycle 78 차원 재정의 trigger #1 자연 발화 evidence (entry 박제 후 7 사이클 만에 자체 메커니즘 작동성 검증)

[question-own-defaults](/wiki/harness-engineering/question-own-defaults) 정합: "10 streak milestone" 자체도 자가 의심 대상 — 산술 단순 카운팅이 아니라 자연 종료 detect + 도메인 직교 진입이 박제 trigger.

## 차원 재정의 trigger

본 entry 박제 후 silent drift family chain 자연 추가 발화 조건:

1. **✅ cycle 71+ 에서 새 영역 발견** — cycle 78 src/lib/github-projects.ts:65 자연 발화 evidence (scripts/ 자연 종료 후 8 사이클 만에 src/ Next.js 코드 영역 첫 직교 진입). 추가 자연 등장 영역 후보 = content/ MDX 위키 / GitHub Actions yaml shell embed / Cloudflare worker TypeScript / src/app + components 잔여 (보존 후보 4건은 의도된 silent 로 판별)
2. **머니볼 fork 추가 transport** — 머니볼 cycle 165+ 가 silent drift family 새 차원 (예: api route handler / sync job concurrency / migration safety / write 측 assertWriteOk) 발견 시 cross-project 자연 transport. cycle 170~172 = write 측 assertWriteOk 통일 transport candidate (origin/main 자율 ingest)
3. **chain dominance 다른 패턴 정착** — review-code 외 chain (closed-loop-design 등) 이 silent fail 가시화 영역에 자연 발화 시 메타 lens 보강. 직전 5 cycle (74~78) 에서 closed-loop-design (74) + skill-evolution (76) 끼워 review-code dominance 균형 (R3 회피 정합)

**차원 재정의 X 시 동작**: silent drift family chain trigger 자체 자연 dormant — 외부 source 부재 → review-code 자체 자연 종료 (cycle 70 dimension-cycle RETRO-ONLY 정합). 본 entry 가 "dormant 도 정합" evidence 박제. cycle 78 dogfood 후 src/ 잔여 18건도 의도된 silent 부분 많아 추가 fork dormant 가능 — 자연 종료 detect 두 번째 단계 가능.
