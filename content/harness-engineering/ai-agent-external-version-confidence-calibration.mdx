AI 에이전트가 외부 패키지나 action 버전을 추천할 때, **학습 컷오프 이후 릴리즈된 버전을 "존재하지 않는다"고 오판하는 패턴**이 있다. 이를 방지하려면 추천 시 불확실성을 명시해야 한다.

## 사례 — cycle 1350 (2026-07-06)

```yaml
# AI 추천: "v5는 없는 버전 — v4로 변경"
uses: actions/checkout@v5  →  uses: actions/checkout@v4
```

**실제**: `actions/checkout@v5`는 2025년 이후 릴리즈된 유효한 버전. 학습 컷오프(Aug 2025) 이후 출시됐으므로 AI 학습 데이터에 없음. 17개 워크플로 모두 v5 사용 성공 중.

**AI가 해야 했던 말**: "v4가 내 학습 데이터 기준 최신입니다. v5에 대한 정보가 없으나 컷오프 이후 릴리즈되었을 가능성이 있습니다 — 현재 repo 사용 현황을 먼저 확인하세요."

## 신뢰도 캘리브레이션 규칙

AI 에이전트가 외부 버전을 추천할 때 다음 분류 기준 적용:

| 상황 | 신뢰도 | 권장 행동 |
|---|---|---|
| 내가 아는 최신 버전 → 현재 코드와 동일 | 높음 | 변경 불필요 |
| 내가 아는 최신 버전 → 현재 코드보다 낮음 | 중간 | 컷오프 이후 릴리즈 가능 — repo 사용 현황 교차 확인 |
| 현재 코드 버전이 내가 알지 못함 | 낮음 | 컷오프 이후 릴리즈 가능성 높음 — 변경 전 반드시 검증 |
| 현재 코드 버전이 다른 파일에서 성공 사용 중 | 높음 | 해당 버전 유효 — AI 지식보다 repo 현황 우선 |

## 적용 대상

- **GitHub Actions**: `uses: owner/action@vN`
- **npm 패키지**: `"package": "^X.Y.Z"` (특히 프레임워크 major 버전)
- **Python 패키지**: `requirements.txt` 버전 핀닝
- **Docker 이미지**: `image:tag` 특히 `:latest`가 아닌 명시 태그

## 올바른 추천 패턴

```
❌ "v5는 없는 버전입니다. v4로 변경하세요."

✅ "내 학습 데이터(Aug 2025 기준)에는 v4가 최신입니다.
   v5 정보가 없으나 컷오프 이후 릴리즈 가능합니다.
   먼저 확인: grep -r 'checkout@' .github/workflows/"
```

## AI 에이전트가 버전 추천을 회피해야 하는 경우

다음 신호가 있으면 버전 변경 추천을 보류하고 사용자/repo 현황 확인을 먼저 요청:

1. **repo 다른 파일에서 같은 버전 사용 중** → 그 버전은 유효
2. **현재 코드 버전 > 내가 아는 최신 버전** → 컷오프 이후 릴리즈
3. **최근 CI 성공 이력이 있는 워크플로의 버전** → 변경 불필요

## 자가 점검 템플릿

버전 변경 추천 전 내부 점검:

```
[ ] 이 버전이 내 학습 컷오프 이후일 수 있는가?
[ ] repo의 다른 파일에서 같은 버전을 사용하고 있는가?
[ ] 해당 버전으로 최근 CI 성공 이력이 있는가?
```

하나라도 해당하면 → 변경 추천 전 "버전 불확실성" 명시.

## 관련 패턴

- **교차 워크플로 감사**: repo 전체 사용 현황이 AI 학습보다 정확
- **fix-stacking 안티패턴**: 잘못된 버전 진단 → 불필요한 변경 누적으로 이어짐
- **최소 변경 원칙**: 불확실한 버전 변경은 하지 않는 것이 기본
