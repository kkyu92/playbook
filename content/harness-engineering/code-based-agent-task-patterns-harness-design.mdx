코딩 에이전트가 복잡한 태스크를 수행할 때, 기존의 UI 기반 툴은 큰 장애물로 작용합니다. UI는 인간 사용자에게 직관적이지만, 에이전트에게는 불확실한 상태, 동적 레이아웃, 클릭 기반의 비결정적 인터랙션을 강요하여 자동화를 어렵게 만듭니다. 이러한 문제를 해결하기 위해, VibeFrame이 비디오 편집에서 '스토리보드 기반 비디오 CLI'를 도입하여 UI 의존성을 해소했듯이, AI 에이전트 하네스(Harness) 역시 코드 기반의 선언적(declarative) 작업 처리 패턴을 채택해야 합니다. 이 접근 방식은 에이전트가 시스템과 일관되고 예측 가능한 방식으로 상호작용할 수 있는 기반을 제공합니다.

## 코드 기반 작업 처리 패턴의 핵심

코드 기반 작업 처리 패턴은 에이전트가 목표를 달성하기 위해 필요한 모든 정보와 단계를 명시적이고 구조화된 코드로 정의하도록 요구합니다. 이는 다음과 같은 특징을 가집니다:

### 1. 선언적 작업 Manifest

에이전트가 수행할 작업은 JSON, YAML 또는 도메인 특화 언어(DSL)와 같은 선언적인 형식으로 작성됩니다. 이 manifest는 '무엇을 할 것인가'를 정의하며, '어떻게 할 것인가'는 하네스 내부의 실행 엔진이 담당합니다. 예를 들어, 클라우드 리소스 프로비저닝 작업은 특정 API를 호출하는 일련의 CLI 명령이 아닌, 최종적인 리소스의 desired state를 기술합니다.

### 2. 모듈형 CLI/API 인터페이스

하네스는 외부 툴이나 서비스와의 모든 상호작용을 에이전트가 호출할 수 있는 명확하고 모듈화된 CLI 명령 또는 API 엔드포인트로 추상화합니다. 이는 에이전트가 복잡한 UI를 파싱하거나 저수준의 HTTP 요청을 직접 구성할 필요 없이, 표준화된 인터페이스를 통해 작업을 지시하고 결과를 받을 수 있게 합니다.

### 3. 상태의 명시적 관리 및 불변성

코드 기반 작업은 상태를 명시적으로 다루고, 가능하다면 불변성(immutability)을 유지하려 노력합니다. 각 작업 단계는 이전 단계의 출력에 의존할 수 있지만, 전체 시스템 상태를 예측 불가능하게 변경하지 않습니다. 이는 에이전트가 작업의 진행 상황을 추적하고 오류 발생 시 롤백 또는 재시도를 용이하게 합니다.

## Harness 설계 원칙 및 구현 예시

하네스는 에이전트가 생성한 코드 기반 manifest를 해석하고 실제 시스템에 명령을 전달하는 브릿지 역할을 합니다. 다음은 Harness 구현을 위한 핵심 원칙입니다.

### 1. Manifest 유효성 검증 및 해석

하네스는 에이전트가 생성한 manifest가 유효한 스키마를 따르는지 검증해야 합니다. 이후, manifest를 파싱하여 개별 작업 단계(task steps)로 분리하고 실행 계획을 수립합니다. 2026년에는 이 유효성 검증 단계에서 LLM 기반의 의미론적(semantic) 검증 기능이 더욱 중요해질 것입니다. 단순히 형식적 유효성을 넘어, manifest의 내용이 실제 환경에서 의도한 결과를 낼 수 있는지 시뮬레이션하거나 예측하는 방향으로 발전할 수 있습니다.

### 2. 도구(Tool) 실행 레이어

각 작업 단계는 특정 외부 툴(예: `kubectl`, `terraform`, 커스텀 CLI)의 호출로 매핑됩니다. 하네스는 이러한 툴 호출을 샌드박스 환경에서 실행하고, 출력(stdout, stderr)을 캡처하여 에이전트에게 반환합니다. 이를 통해 에이전트는 저수준의 실행 세부사항에 신경 쓰지 않고, 고수준의 작업 목표에 집중할 수 있습니다.

```python
# task_manifest.json - 에이전트가 생성하거나 수정할 수 있는 선언적 작업 명세
{
  "workflow_name": "provision_cloud_resource",
  "description": "Agent-driven cloud resource provisioning workflow",
  "steps": [
    {
      "name": "create_resource_group",
      "tool": "az_cli",
      "command": "group create",
      "args": {
        "name": "my-agent-rg-{random_suffix}",
        "location": "eastus"
      },
      "outputs": ["id", "name", "location"]
    },
    {
      "name": "deploy_web_app",
      "tool": "az_cli",
      "command": "webapp up",
      "args": {
        "resource-group": "{{create_resource_group.name}}",
        "name": "agent-webapp-{random_suffix}",
        "html-path": "./app_code"
      },
      "dependencies": ["create_resource_group"],
      "outputs": ["id", "hostnames"]
    }
  ]
}

# harness_executor.py - 코드 기반 manifest를 실행하는 하네스 예시
import json
import subprocess
import os
import uuid

class AgentHarnessExecutor:
    def __init__(self, tools_config: dict):
        self.tools = tools_config
        self.results = {}
        self.context = {"random_suffix": str(uuid.uuid4())[:8]}

    def _resolve_args(self, args: dict) -> dict:
        resolved_args = {}
        for key, value in args.items():
            if isinstance(value, str):
                # Resolve dependencies like {{step_name.output_key}}
                if value.startswith("{{") and value.endswith("}}"):
                    dep_ref = value[2:-2].split('.')
                    if len(dep_ref) == 2:
                        dep_step_name, output_key = dep_ref
                        if dep_step_name in self.results:
                            resolved_args[key] = self.results[dep_step_name].get(output_key)
                        else:
                            raise ValueError(f"Dependency {dep_step_name}.{output_key} not resolved in _resolve_args.")
                    else:
                         raise ValueError(f"Invalid dependency format: {value}")
                # Resolve context variables like {random_suffix}
                elif "{" in value and "}" in value:
                    resolved_args[key] = value.format(**self.context)
                else:
                    resolved_args[key] = value
            else:
                resolved_args[key] = value
        return resolved_args

    def execute_step(self, step: dict) -> bool:
        step_name = step["name"]
        tool_name = step["tool"]
        command_base = step["command"]
        raw_args = step["args"]

        resolved_args = self._resolve_args(raw_args)

        if tool_name == "az_cli":
            full_command = [self.tools["az_cli_path"], *command_base.split()]
            for key, value in resolved_args.items():
                full_command.extend([f"--{key}", str(value)])
            
            print(f"Executing step '{step_name}': {' '.join(full_command)}")
            try:
                # Mock subprocess for safe demonstration, remove for actual execution
                if os.getenv("HARNESS_MOCK_MODE", "true").lower() == "true":
                    print(f"[MOCK] Would execute: {' '.join(full_command)}")
                    mock_output = {"id": f"mock-id-{step_name}", "name": resolved_args.get("name", step_name), "location": resolved_args.get("location", "mock-location"), "hostnames": [f"mock-app-{step_name}.azurewebsites.net"]}
                    self.results[step_name] = {k: mock_output.get(k) for k in step.get("outputs", [])}
                    print(f"[MOCK] Step '{step_name}' completed. Output: {self.results[step_name]}")
                    return True

                # Actual execution path (requires 'az' CLI installed and logged in)
                result = subprocess.run(full_command, capture_output=True, text=True, check=True)
                output = json.loads(result.stdout) # Assuming JSON output from AZ CLI
                step_result = {k: output.get(k) for k in step.get("outputs", [])}
                self.results[step_name] = step_result
                print(f"Step '{step_name}' completed. Output: {step_result}")
                return True
            except subprocess.CalledProcessError as e:
                print(f"Error executing step '{step_name}': {e.stderr}")
                return False
            except json.JSONDecodeError:
                print(f"Warning: Non-JSON output or empty output for step '{step_name}'. Raw: {result.stdout.strip()}")
                self.results[step_name] = {"raw_output": result.stdout.strip()} # Store raw output for debugging
                return True 
            except Exception as e:
                print(f"Unexpected error in step '{step_name}': {e}")
                return False
        else:
            print(f"Unknown tool: {tool_name}")
            return False

    def run_workflow(self, workflow_manifest: dict) -> bool:
        for step in workflow_manifest["steps"]:
            # Basic dependency handling: check if dependencies are met
            if "dependencies" in step:
                for dep in step["dependencies"]:
                    if dep not in self.results:
                        print(f"Error: Dependency '{dep}' for step '{step['name']}' not met.")
                        return False
            
            if not self.execute_step(step):
                print(f"Workflow failed at step: {step['name']}")
                return False
        print("Workflow completed successfully.")
        return True

# --- Usage Example (requires task_manifest.json to exist) ---
if __name__ == "__main__":
    # Configure tools, e.g., path to Azure CLI executable
    tools_config = {
        "az_cli_path": "az" 
    }
    executor = AgentHarnessExecutor(tools_config)

    try:
        with open("task_manifest.json", "r", encoding="utf-8") as f:
            manifest = json.load(f)
        
        print("--- Starting Agent Workflow Simulation ---")
        # In a real scenario, an LLM agent would generate or refine `manifest`
        # and then invoke `executor.run_workflow(manifest)`.
        # Set HARNESS_MOCK_MODE=false in environment to attempt actual execution (CAUTION!)
        if os.getenv("HARNESS_MOCK_MODE", "true").lower() == "true":
            print("Running in MOCK_MODE. No actual CLI commands will be executed.")
        else:
            print("Running in LIVE_MODE. Requires 'az' CLI installed and logged in.")
        
        executor.run_workflow(manifest)
        print("--- Agent Workflow Simulation Complete ---")

    except FileNotFoundError:
        print("Error: 'task_manifest.json' not found. Please create it first.")
    except json.JSONDecodeError:
        print("Error: 'task_manifest.json' is not a valid JSON file.")
    except Exception as e:
        print(f"An unexpected error occurred: {e}")
```

### 3. 피드백 루프 및 상태 업데이트

하네스는 작업 실행 결과를 캡처하여 에이전트에게 구조화된 형태로 반환합니다. 이 정보는 에이전트가 다음 행동을 결정하거나, 오류를 진단하고, 학습 데이터를 구축하는 데 활용됩니다. 2026년에는 이 피드백 루프가 더욱 정교해져, 단순한 성공/실패 여부를 넘어 작업의 경제적 효율성, 보안 취약점, 규정 준수 여부 등 다차원적인 메트릭을 포함할 것입니다.

## 트레이드오프

이 코드 기반 작업 처리 패턴은 여러 이점을 제공하지만, 동시에 고려해야 할 트레이드오프도 존재합니다.

*   **초기 개발 복잡성**: 선언적 manifest 스키마 설계 및 견고한 하네스 구현은 상당한 초기 엔지니어링 노력을 요구합니다. 
    *   **언제 좋고**: 장기적인 자동화 효율성, 재사용성, 에이전트의 안정적인 동작이 중요한 대규모 프로젝트나 핵심 워크로드에 적합합니다.
    *   **언제 나쁜지**: 빠른 프로토타이핑이나 단순 일회성 태스크에는 과도한 오버헤드일 수 있습니다.
*   **학습 곡선**: 에이전트 개발자 또는 하네스를 사용하는 엔지니어는 manifest 스키마와 하네스의 동작 방식을 숙지해야 합니다. 
    *   **언제 좋고**: 명확한 스키마는 팀 내 협업을 촉진하고 일관된 자동화 표준을 수립하는 데 도움이 됩니다.
    *   **언제 나쁜지**: 비전문가나 빠르게 결과를 내야 하는 상황에서는 UI가 제공하는 즉각적인 피드백과 직관성이 부족하여 생산성이 저하될 수 있습니다.
*   **범용성 vs. 도메인 특화**: 하네스가 특정 도메인(예: 클라우드 인프라, 데이터 파이프라인)에 최적화될수록 에이전트의 효율성은 높아지지만, 다른 도메인으로의 확장성은 저해될 수 있습니다. 
    *   **언제 좋고**: 특정 비즈니스 도메인에서 높은 수준의 자동화와 정확성이 요구될 때 탁월한 성능을 발휘합니다.
    *   **언제 나쁜지**: 다양한 종류의 태스크를 처리해야 하는 범용 에이전트 플랫폼에는 유연성이 부족할 수 있습니다.
*   **실시간 피드백 부족**: 코드 기반은 시각적인 UI에 비해 실시간 작업 진행 상황을 직관적으로 확인하기 어렵습니다. 
    *   **언제 좋고**: 상세한 로그와 메트릭을 통해 정확한 진단과 사후 분석이 가능하여, 에러 발생 시 디버깅에 유리합니다.
    *   **언제 나쁜지**: 개발/디버깅 단계에서 즉각적인 시각적 결과나 중간 상태 확인이 필요한 경우 답답함을 느낄 수 있습니다.

## 실전 체크리스트

코딩 에이전트를 위한 코드 기반 작업 처리 패턴을 프로젝트에 적용할 때 다음 사항들을 검증해야 합니다.

- [ ] 모든 핵심 자동화 태스크가 선언적 manifest (JSON, YAML 등)로 완전히 표현 가능한가?
- [ ] 각 태스크 manifest 스키마가 명확하게 정의되어 있으며, 에이전트가 이를 안정적으로 생성 및 검증할 수 있는가?
- [ ] 하네스가 에이전트가 생성한 manifest를 파싱하고, 유효성을 검증하며, 실행 계획을 수립하는 견고한 로직을 가지고 있는가?
- [ ] 외부 툴(CLI, API)과의 인터페이스가 모듈화되어 있으며, 샌드박스 환경에서 안전하게 실행되는가?
- [ ] 에이전트가 작업을 실행한 후, 그 결과를 구조화된 형태로 수신하고 다음 행동을 결정하는 피드백 루프가 효과적으로 작동하는가?
- [ ] 작업 실행 중 발생하는 오류에 대한 처리 전략(재시도, 롤백, 에이전트에게 피드백)이 명확하게 정의되어 있는가?
- [ ] 복잡한 워크플로를 위해 여러 태스크 manifest를 조합하고 의존성을 관리하는 추상화 메커니즘이 제공되는가?
