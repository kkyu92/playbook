기술 스택의 복잡성이 증가하고 LLM 기반 에이전트 시스템과 같은 모듈형 아키텍처가 확산됨에 따라, 견고하고 유지보수 가능한 코드베이스를 구축하는 것이 더욱 중요해지고 있습니다. 이 과정에서 공개 함수(Public Function) 설계 원칙은 핵심적인 역할을 합니다. 특히, 하나의 공개 함수가 다른 공개 함수를 직접 호출하는 패턴을 지양하고 비공개 헬퍼 함수(Private Helper Function)를 통해 공통 로직을 재사용하는 접근 방식은 API의 응집도를 높이고 내부 구현의 유연성을 확보하는 데 필수적입니다.

## 왜 공개 함수는 다른 공개 함수를 호출하지 않아야 하는가?

공개 함수는 시스템의 외부 인터페이스(API)를 정의하며, 외부 호출자와의 계약(Contract)을 형성합니다. 이러한 계약은 안정적이고 예측 가능해야 합니다. 만약 공개 함수 A가 공개 함수 B를 호출하도록 구현된다면, 다음과 같은 문제가 발생할 수 있습니다.

1.  **결합도 증가 (Increased Coupling):** 공개 함수 A와 B가 서로에게 강하게 의존하게 되어 내부 구현의 변경이 다른 공개 함수의 동작에 영향을 미치기 쉽습니다. 이는 유지보수를 어렵게 하고 예상치 못한 부작용을 초래할 수 있습니다.
2.  **테스트의 어려움 (Testing Difficulty):** 공개 함수를 테스트할 때, 해당 함수가 호출하는 다른 공개 함수까지 함께 테스트되어야 하므로 단위 테스트의 독립성이 저해됩니다. 이는 테스트 코드의 복잡성을 증가시키고 버그 진단을 어렵게 합니다.
3.  **API 계약의 모호성 (Ambiguity in API Contracts):** 외부 사용자 관점에서 어떤 공개 함수가 내부적으로 다른 공개 함수를 호출하는지 알기 어렵습니다. 이는 API 사용 패턴을 혼란스럽게 만들고, 불필요한 의존성을 강요할 수 있습니다.
4.  **내부 구현 유연성 저하 (Reduced Internal Flexibility):** 공개 함수가 내부 로직을 재사용할 때, 외부 API의 제약 조건이 내부 구현에까지 영향을 미쳐 유연한 변경을 방해합니다. 내부 로직은 외부 계약과 무관하게 자유롭게 발전할 수 있어야 합니다.

이러한 문제를 해결하기 위해, 공개 함수 간에 공통 로직을 재사용해야 할 경우 비공개(Private) 헬퍼 함수를 추출하여 두 공개 함수가 이 헬퍼 함수를 호출하도록 하는 것이 권장됩니다. 이 방식은 내부 구현의 세부 사항을 캡슐화하고, 공개 API의 계약을 명확하게 유지합니다.

## 코드 예제: 공개 함수 리팩토링

다음 Python 코드 예제를 통해 공개 함수 간 직접 호출을 비공개 헬퍼 함수로 리팩토링하는 과정을 살펴보겠습니다. 이 예제는 LLM 에이전트가 특정 작업을 수행하는 시나리오를 가정합니다.

### 초기 (Bad Practice) 코드

```python
# agent_operations.py

class AgentService:
    def __init__(self):
        pass

    def public_process_data(self, data: str) -> str:
        """공개 데이터 처리 함수"""
        print(f"[Public] Processing data: {data}")
        processed_intermediate = self.public_validate_data(data) # 공개 함수가 다른 공개 함수 호출
        final_result = f"Final processed: {processed_intermediate.upper()}"
        return final_result

    def public_validate_data(self, data: str) -> str:
        """공개 데이터 검증 함수"""
        print(f"[Public] Validating data: {data}")
        if len(data) < 5:
            raise ValueError("Data too short for validation")
        return f"Validated_{data}"

# 사용 예시
service = AgentService()
# print(service.public_process_data("testdata"))
# print(service.public_validate_data("long_test_data"))
```

위 코드에서 `public_process_data`는 `public_validate_data`를 직접 호출합니다. 이는 두 공개 함수 간의 내부적 결합을 생성합니다. 이제 이를 리팩토링하여 비공개 헬퍼 함수를 도입하겠습니다.

### 리팩토링된 (Good Practice) 코드

```python
# agent_operations_refactored.py

class AgentServiceRefactored:
    def __init__(self):
        pass

    def _private_common_validation(self, data: str) -> str:
        """비공개 공통 데이터 검증 헬퍼 함수"""
        print(f"[Private Helper] Performing common validation for: {data}")
        if len(data) < 5:
            raise ValueError("Data too short for common validation")
        return f"Common_Validated_{data}"

    def public_process_data(self, data: str) -> str:
        """공개 데이터 처리 함수"""
        print(f"[Public] Initiating data processing: {data}")
        # 비공개 헬퍼 함수 호출
        processed_intermediate = self._private_common_validation(data)
        final_result = f"Final processed: {processed_intermediate.upper()}"
        return final_result

    def public_validate_data(self, data: str) -> str:
        """공개 데이터 검증 함수"""
        print(f"[Public] Initiating data validation: {data}")
        # 비공개 헬퍼 함수 호출
        validated_data = self._private_common_validation(data)
        return f"Public_Validated_{validated_data}"

# 사용 예시
service_refactored = AgentServiceRefactored()
# print(service_refactored.public_process_data("testdata_long"))
# print(service_refactored.public_validate_data("another_long_data"))
```

리팩토링된 코드에서는 `_private_common_validation`이라는 비공개 헬퍼 함수가 추출되어 `public_process_data`와 `public_validate_data`가 공통 로직을 공유하면서도 서로에게 직접 의존하지 않게 되었습니다. 파이썬에서는 관례적으로 비공개 함수에 `_` 프리픽스를 붙입니다.
