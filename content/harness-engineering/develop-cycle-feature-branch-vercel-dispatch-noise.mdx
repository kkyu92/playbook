## 패턴

develop-cycle 이 multi-step plan 을 실행할 때 feature branch 에 여러 차례 push 가 발생:

```
develop-cycle plan N step 1 push → Vercel preview fail → dispatch → 허브 issue
develop-cycle plan N step 2 push → Vercel preview fail → dispatch → 허브 issue
...
develop-cycle plan N step 4 merged → CI pass → dispatch skipped
                                   → Vercel production pass
```

각 push 마다 `Vercel Deploy Failure Dispatch` 또는 `CI Failure Dispatch` 워크플로가 발화. 중간 단계 실패는 이후 push 에서 자동 해결되지만, 각 실패당 허브에 별도 issue 가 생성된다.

## 왜 이게 구조적 노이즈인가

| 구분 | 특성 |
|---|---|
| 출처 | develop-cycle feature branch (develop-cycle/cycle-NNN-plan-X-stepY) |
| 타이밍 | plan 중간 단계 — 의도적 실험/반복 중 |
| 해소 | plan 완료 시 자연 superseded (branch 삭제, main merge 성공) |
| 허브 impact | N개 feature branch push × M 실패 = N×M inbound issue 누적 |
| 재발 패턴? | 아님 — 동일 commit/branch 재발 X, 후속 plan step 이 해결 |

## 탐지 기준 (stale 판단)

```
1. Issue label: inbound + incident
2. Fingerprint: vercel-deploy-<commitSHA> 또는 ci-develop-cycle-cycle-NNN
3. Commit SHA grep: develop-cycle/cycle-NNN branch (현재 branch 존재 여부 확인)
4. Moneyball current cycle >> NNN (이미 진행됨 = superseded 확정)
```

stale 판단 시 **일괄 close** 가능 (개별 root cause 분석 불필요).

## 운영 전략

### 즉시 (현재)

batch-close with comment:
```
develop-cycle feature branch 중간 단계 실패 — plan 완료 확인 (cycle NNN superseded).
재발 패턴 아님. 단발 branch deploy.
```

### 장기 고려

`Vercel Deploy Failure Dispatch` 워크플로에 develop-cycle branch 필터 추가:

```yaml
# .github/workflows/vercel-deploy-failure-dispatch.yml
if: |
  !startsWith(github.ref, 'refs/heads/develop-cycle/') &&
  !startsWith(github.ref, 'refs/heads/develop-cycle-blog/')
```

→ feature branch Vercel 실패 = dispatch X (허브에 issue 생성 X).

**단점**: develop-cycle branch 의 production-breaking failure 놓칠 수 있음 (드물지만 가능). 현재 phase 에서는 signal/noise 비율 평가 후 결정.
