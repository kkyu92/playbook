## 이것이 문제인가?

### 문제 아닌 이유

**JIT 의미 검색이 암묵적 그래프를 형성한다**. `node scripts/search.mjs "<query>"` 는 embeddings 기반 의미 유사성으로 카테고리 경계를 넘어 관련 chunks를 반환. agents/evaluation/context-engineering 간 명시적 연결이 0이어도 검색은 이들을 연결한다.

즉, **connections frontmatter = 편집 큐레이션 마커** (사람이 "이 entry는 저 entry와 함께 읽어라"는 신호), **검색 = 실제 지식 그래프 traversal**.

### 문제인 이유

**cross-category 편집 큐레이션이 전무하다**. agents/evaluation/harness-engineering 간 명시적 연결 = 0건. 예:
- `evaluation` entry가 `harness-engineering` 패턴을 증거로 인용해야 할 때 connection 부재
- `agents` entry의 insight가 `harness-engineering` 설계에 영향줄 때 추적 불가

편집 큐레이션이 없으면 wiki는 카테고리별 독립 파일 더미 → knowledge graph 아님.

## Orphan Link 패턴

deletion 시 역방향 연결 미정리 = orphan link 생성. 수동 체크:

```bash
python3 -c "
import os, re, glob

mdx_files = glob.glob('content/**/*.mdx', recursive=True)
all_slugs = set(os.path.basename(f).replace('.mdx','') for f in mdx_files)

for f in mdx_files:
    content = open(f).read()
    m = re.search(r'connections:\s*\n((?:\s*-\s*.+\n)*)', content)
    if m:
        for c in re.findall(r'-\s*(.+)', m.group(1)):
            slug = c.strip().split('/')[-1]
            if slug and slug not in all_slugs:
                print(f'ORPHAN: {os.path.basename(f)} -> {slug}')
"
```

2026-05-22 실측: 2건 (YAML 파싱 artifact 포함). `closed-loop-health` 은 3개 entry에서 참조되지만 해당 파일 부재 → 실제 orphan 1건.

## curate 시 권장 행동

1. **새 entry 생성 시**: connections 최소 1개 의무 (CLAUDE.md 규칙)
2. **curate chain 실행 시**: cross-category connection 후보 1~2건 추가 (같은 카테고리 내 연결만 X)
3. **orphan link 스캔**: 위 bash script로 삭제 entry 참조 정리
4. **agents / evaluation / context-engineering**: 단발 entry 생성 시 harness-engineering 연결 1건 이상 추가 권장
