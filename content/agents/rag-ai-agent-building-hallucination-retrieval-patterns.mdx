## RAG 기반 AI 에이전트 구축 패턴

AI 에이전트가 복잡한 태스크를 수행할 때 발생하는 환각(hallucination) 문제는 핵심적인 해결 과제입니다. RAG (Retrieval-Augmented Generation) 패턴은 외부 지식 소스에서 관련 정보를 검색하여 LLM의 컨텍스트를 풍부하게 하고, 이를 기반으로 답변을 생성함으로써 에이전트의 신뢰성과 정확성을 향상시키는 핵심 전략입니다.

### RAG의 핵심 원리

RAG는 크게 세 가지 단계로 구성됩니다:

1.  **Retrieval (정보 검색)**: 에이전트의 쿼리에 대해 외부 지식 저장소(Vector DB, Knowledge Graph)에서 가장 관련성 높은 문서를 검색합니다. 쿼리 및 문서 임베딩, 유사도 검색이 활용됩니다.
2.  **Augmentation (컨텍스트 증강)**: 검색된 정보를 원본 쿼리와 함께 LLM의 프롬프트 컨텍스트에 추가합니다. 이는 LLM이 정확한 답변을 생성하는 데 필요한 근거를 제공합니다.
3.  **Generation (응답 생성)**: 증강된 컨텍스트를 바탕으로 LLM은 최종 응답을 생성합니다. LLM은 제공된 정보 내에서 답변을 도출하도록 지시받아 환각을 최소화합니다.

이 패턴은 에이전트가 미리 학습된 모델의 지식 범위를 넘어 실시간 데이터, 사내 문서 등 최신 외부 정보를 활용하게 합니다.

### RAG 기반 AI 에이전트 구축 패턴

RAG를 AI 에이전트에 통합하는 다양한 패턴은 에이전트의 복잡성과 요구사항에 따라 선택됩니다.

#### 1. 기본 RAG 에이전트 (Basic RAG Agent)

사용자의 단일 쿼리에 대해 한 번의 검색-증강-생성 사이클을 수행합니다. 간단한 질의응답 시스템에 적합합니다.

```python
# Python (Pseudocode for Basic RAG)
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_core.documents import Document # Added for clarity

# 1. Document Loading and Indexing
# Assuming 'docs' is a list of Document objects, e.g., [Document(page_content="RAG is...", metadata={"source": "wiki"})]
docs = [Document(page_content="RAG (Retrieval Augmented Generation) combines information retrieval with text generation to improve the factual accuracy and reduce hallucinations of large language models (LLMs). It works by first retrieving relevant information from a knowledge base and then using that information to augment the prompt given to the LLM.", metadata={"source": "rag_doc"})]
text_splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
chunks = text_splitter.split_documents(docs)
vectorstore = FAISS.from_documents(chunks, OpenAIEmbeddings())
retriever = vectorstore.as_retriever()

# 2. Define LLM and Prompt
llm = ChatOpenAI(model="gpt-4o", temperature=0) # Using a 2026-relevant model
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are an AI assistant. Answer the user's question based on the provided context only. If the context does not contain enough information, state that you cannot answer based on the given context."),
    ("user", "Context: {context}\nQuestion: {question}")
])

# 3. Build RAG Chain
rag_chain = prompt | llm | StrOutputParser()

def basic_rag_query(query: str):
    retrieved_docs = retriever.invoke(query)
    context = "\\n\\n".join(doc.page_content for doc in retrieved_docs)
    return rag_chain.invoke({"context": context, "question": query})

# Example Usage
# response = basic_rag_query("RAG의 작동 원리는 무엇인가?")
# print(response)
```

#### 2. 에이전트 주도형 RAG (Agentic RAG)

에이전트가 쿼리를 변형하거나, 여러 번의 검색을 통해 정보를 정제합니다.

*   **Query Rewriting**: 원본 쿼리를 검색에 더 적합한 하위 쿼리로 재작성합니다.
*   **Hybrid Retrieval**: 벡터 검색과 키워드 검색을 결합하여 다양한 유형의 검색에 대응합니다.
*   **Contextual Reranking**: 초기 검색된 문서들을 에이전트의 판단에 따라 재순위화합니다.

#### 3. 다단계 RAG (Multi-Hop RAG)

단일 검색으로는 불충분한 복잡한 질문에 대해, 에이전트가 여러 RAG 사이클을 수행하여 정보를 심층적으로 탐색합니다. 이전 검색 결과를 바탕으로 새로운 질문을 생성하고 응답을 정교화합니다.

```mermaid
graph TD
    A[사용자 쿼리] --> B{에이전트 판단};
    B -- 복잡한 쿼리 --> C[쿼리 분해/재작성];
    C --> D[정보 검색];
    D --> E[검색 결과 Reranking];
    E --> F{LLM (컨텍스트 증강 & 생성)};
    F -- 추가 정보 필요 --> C;
    F -- 최종 응답 생성 --> G[최종 사용자 응답];
    B -- 간단한 쿼리 --> D;
    F -- 응답 완료 --> G;

    subgraph RAG_Cycle
        D --- E --- F
    end
```

#### 4. 동적 RAG (Dynamic RAG)

에이전트의 태스크나 현재 상태에 따라 검색 전략, 지식 저장소, 임베딩 모델을 동적으로 변경합니다. 이는 에이전트가 다양한 도메인과 상황에 유연하게 대응하도록 합니다.

#### 5. 멀티모달 RAG (Multimodal RAG) 및 Knowledge Graph 통합

2026년 트렌드로, 텍스트뿐만 아니라 이미지, 오디오 등 다양한 형태의 데이터를 검색하고 활용합니다. 또한, 단순 텍스트 검색을 넘어 Knowledge Graph의 구조화된 지식을 RAG에 활용하여 더 정확하고 추론 가능한 답변을 제공하는 패턴이 발전하고 있습니다.

## 트레이드오프

### 1. 검색 정확도 vs. 검색 속도
*   **언제 좋고**: 높은 검색 정확도는 에이전트의 환각을 최소화하고 신뢰성 높은 답변을 보장합니다. 다단계 검색, 복잡한 Reranking, 고급 청킹 전략이 포함됩니다.
*   **언제 나쁜지**: 정확도 향상을 위한 복잡한 연산은 검색 속도를 저하시켜 실시간 응답이 필수적인 애플리케이션에 부적합합니다. 초기 쿼리 변형, 여러 라운드 정보 추출, 재순위 지정 등은 응답 지연을 야기합니다.

### 2. 컨텍스트 크기 vs. 비용 및 지연 시간
*   **언제 좋고**: LLM에 더 많은 관련 컨텍스트를 제공할수록 답변의 품질과 정확도가 높아집니다. 깊은 이해와 상세한 응답이 필요할 때 유리합니다.
*   **언제 나쁜지**: LLM 컨텍스트 윈도우 크기는 제한적이며, 많은 토큰을 처리할수록 비용이 증가하고 응답 지연이 길어집니다. 불필요한 정보는 '노이즈'가 되어 성능을 저하시킬 수 있습니다.

### 3. 지식 업데이트 주기 vs. 시스템 복잡성 및 일관성
*   **언제 좋고**: 실시간 또는 빈번한 지식 업데이트는 에이전트가 항상 최신 정보를 활용하게 합니다. 빠르게 변하는 도메인(뉴스, 주식)에 필수적입니다.
*   **언제 나쁜지**: 잦은 업데이트는 벡터 데이터베이스 재인덱싱 또는 캐시 무효화와 같은 오버헤드를 발생시키고, 시스템의 복잡성과 일관성 유지에 어려움을 초래합니다.

## 실전 체크리스트

프로젝트에 RAG 기반 AI 에이전트 패턴을 적용할 때 다음 항목들을 검토해야 합니다.

- [ ] **데이터 수집 및 청킹 전략 최적화**: 에이전트가 활용할 외부 지식 소스를 명확히 하고, 효과적인 청킹 및 메타데이터 추출 전략이 수립되었는가?
- [ ] **임베딩 모델 및 벡터 DB 선정/평가**: 프로젝트 요구사항에 적합한 임베딩 모델과 벡터 데이터베이스를 선정하고, 검색 정확도, 속도, 비용을 정량적으로 평가했는가?
- [ ] **쿼리 변형 및 재순위화 로직 구현 여부**: 사용자 쿼리를 검색에 최적화하고, 검색된 문서를 컨텍스트에 맞게 재순위화하는 로직이 적절하게 구현되었는가? (참고: `agents/agentic-context-compaction-trigger-heuristics`)
- [ ] **환각 감지 및 완화 메커니즘 통합**: 에이전트 생성 응답의 사실성을 검증하고, 환각 감지 시 이를 알리거나 자체 수정하는 메커니즘(참고: `evaluation/generative-ai-hallucination-automated-detection-evaluation`)이 포함되었는가?
- [ ] **LLM의 컨텍스트 활용 효율성 모니터링**: LLM이 제공된 RAG 컨텍스트를 효과적으로 활용하는지, 불필요한 정보로 인한 노이즈 발생 여부를 지속적으로 모니터링하고 있는가?
- [ ] **RAG 파이프라인 성능 및 비용 모니터링 시스템 구축**: 검색 시간, 토큰 사용량 등 RAG 파이프라인의 핵심 지표들을 모니터링하고, 성능 저하 또는 비용 증가 발생 시 대응할 수 있는 알림 시스템이 구축되었는가? (참고: `harness-engineering/rag-pipeline-performance-cost-optimization-patterns`)
- [ ] **지식 베이스 업데이트 자동화 및 관리**: RAG 지식 베이스의 신선도를 유지하기 위한 업데이트 주기 및 자동화 프로세스가 명확하게 정의되고 관리되고 있는가?
