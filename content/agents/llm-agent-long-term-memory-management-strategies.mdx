LLM 기반 에이전트가 복잡하고 장기적인 목표를 달성하려면 일시적인 컨텍스트 윈도우 한계를 넘어선 '장기 기억' 시스템이 필수적입니다. 이 장기 기억은 에이전트가 과거의 경험, 학습된 지식, 지속적인 대화 컨텍스트를 유지하고 활용하여 일관된 행동과 향상된 의사결정을 가능하게 합니다. 2026년 에이전트 아키텍처는 이러한 기억 관리 메커니즘을 중심으로 발전하고 있습니다.

## 장기 기억 관리 아키텍처

LLM 에이전트의 장기 기억은 주로 외부 저장소를 활용하여 LLM의 제한된 컨텍스트 윈도우를 보완합니다. 핵심 전략들은 다음과 같습니다.

### Retrieval Augmented Generation (RAG)

RAG는 LLM이 외부 지식 기반에서 관련 정보를 검색하여 응답을 생성하는 방식입니다. 에이전트는 작업 수행 중 필요한 정보를 장기 기억 저장소에서 검색하여 LLM의 프롬프트 컨텍스트에 추가합니다. 이는 에이전트의 지식 기반을 확장하고 환각(hallucination)을 줄이는 데 효과적입니다.

일반적인 RAG 구성 요소:
*   **정보 저장소 (Knowledge Base)**: 에이전트의 모든 경험, 관찰, 학습된 정보가 저장됩니다. 텍스트 문서, 코드, 데이터베이스 등 다양한 형태가 될 수 있습니다.
*   **임베딩 모델 (Embedding Model)**: 저장된 정보를 고차원 벡터 공간의 임베딩으로 변환합니다.
*   **벡터 데이터베이스 (Vector Database)**: 임베딩된 정보를 저장하고 유사성 검색(similarity search)을 효율적으로 수행합니다. (예: Pinecone, Weaviate, Qdrant)
*   **검색 전략 (Retrieval Strategy)**: 쿼리와 가장 유사한 정보를 찾아내는 방법 (예: Top-K, MMR, Re-ranking).

```python
from typing import List, Dict
from collections import defaultdict

# Mocking a basic vector database and embedding model for demonstration
class MockEmbeddingModel:
    def embed(self, text: str) -> List[float]:
        # In a real scenario, this would generate actual embeddings
        # For simplicity, we just use a hash for 'similarity'
        return [float(hash(text) % 1000) / 1000.0]

class MockVectorDB:
    def __init__(self):
        self.store = defaultdict(list)
        self.documents = []

    def add(self, text: str, embedding: List[float]):
        self.documents.append({"text": text, "embedding": embedding})

    def search(self, query_embedding: List[float], top_k: int = 3) -> List[Dict]:
        # Simple 'similarity' based on the mock embedding
        scored_docs = []
        for doc in self.documents:
            # A real vector DB would use cosine similarity or other metrics
            similarity = abs(query_embedding[0] - doc["embedding"][0]) # Inverse for mock
            scored_docs.append((1 - similarity, doc["text"]))
        scored_docs.sort(key=lambda x: x[0], reverse=True)
        return [{"text": doc_text} for score, doc_text in scored_docs[:top_k]]

class LLMAgentMemoryManager:
    def __init__(self):
        self.embedding_model = MockEmbeddingModel()
        self.vector_db = MockVectorDB()
        self.episodic_memory = [] # For storing raw experiences chronologically

    def add_experience(self, experience: str):
        self.episodic_memory.append(experience)
        embedding = self.embedding_model.embed(experience)
        self.vector_db.add(experience, embedding)
        print(f"[Memory] Added experience: '{experience}'")

    def retrieve_relevant_memory(self, query: str, top_k: int = 3) -> List[str]:
        query_embedding = self.embedding_model.embed(query)
        results = self.vector_db.search(query_embedding, top_k)
        return [res["text"] for res in results]

    def reflect_on_experiences(self):
        # In a real scenario, an LLM would summarize/abstract episodic memory
        if len(self.episodic_memory) > 5: # Trigger reflection after some experiences
            recent_experiences = "\n".join(self.episodic_memory[-5:])
            print(f"[Reflection] Reflecting on recent experiences: {recent_experiences[:50]}...")
            # LLM would generate insights or summarized memories here
            # Example: "Based on recent interactions, users often ask about X."
            # These insights could then be added back to vector_db as semantic memory.
            self.episodic_memory = self.episodic_memory[-2:] # Keep some recent, discard older

# Usage example
memory_manager = LLMAgentMemoryManager()
memory_manager.add_experience("사용자가 프로젝트 초기 설정에 대해 질문했다.")
memory_manager.add_experience("프로젝트 A는 데이터베이스 마이그레이션이 필요하다.")
memory_manager.add_experience("다음 작업은 사용자 인증 모듈 개발이다.")
memory_manager.add_experience("프로젝트 B에서는 AWS S3 통합이 중요하다.")
memory_manager.add_experience("사용자가 다시 프로젝트 설정 가이드를 요청했다.")

query = "프로젝트 설정 관련 정보를 찾아줘."
relevant_memories = memory_manager.retrieve_relevant_memory(query)
print(f"\n[Retrieval] Query: '{query}'")
print(f"[Retrieval] Relevant memories: {relevant_memories}")

memory_manager.reflect_on_experiences()

relevant_memories = memory_manager.retrieve_relevant_memory(query)
```

### 에피소드 기억 및 의미론적 기억 (Episodic & Semantic Memory)

*   **에피소드 기억 (Episodic Memory)**: 에이전트의 특정 경험, 상호작용, 관찰 내용을 시간 순서대로 저장합니다. 이는 마치 일기장처럼 '무슨 일이 언제 일어났는지'에 대한 원본 데이터를 제공합니다. 위 코드의 `episodic_memory`가 이에 해당합니다.
*   **의미론적 기억 (Semantic Memory)**: 에피소드 기억에서 추상화되거나 일반화된 지식, 규칙, 개념을 저장합니다. 예를 들어, 반복적인 경험을 통해 '사용자들은 특정 기능에 대해 자주 질문한다'는 통찰을 얻는 것이 의미론적 기억의 일부입니다. RAG 시스템에서 벡터 데이터베이스에 저장되는 요약이나 통찰이 여기에 해당할 수 있습니다.

### 반영 및 자기 개선 (Reflection & Self-Correction)

에이전트는 단순히 정보를 저장하고 검색하는 것을 넘어, 자신의 과거 경험을 '반영(reflect)'하여 새로운 통찰을 도출하고 행동 전략을 개선할 수 있습니다. LLM은 과거의 에피소드 기억들을 분석하고, 패턴을 식별하며, 미래의 행동 계획에 영향을 미칠 수 있는 고수준의 의미론적 기억을 생성할 수 있습니다. 이는 에이전트의 학습 능력을 향상시키고, 장기적인 목표 달성 역량을 강화합니다. 2026년에는 에이전트의 자기 성찰 메커니즘이 더욱 정교해져, 비판적 사고와 전략적 계획 수립에 기여할 것으로 예상됩니다.

### 계층적 기억 시스템 (Hierarchical Memory Systems)

복잡한 에이전트는 단일 기억 시스템 대신 여러 계층의 기억을 활용합니다. 각 계층은 다른 시간 척도와 추상화 수준에서 작동하며, 필요에 따라 정보를 상호 교환합니다.

*   **단기 기억 (Short-Term Memory)**: LLM의 컨텍스트 윈도우 자체. 현재 대화 턴, 즉각적인 입력 및 출력. 휘발성.
*   **중기 기억 (Medium-Term Memory / Scratchpad)**: 현재 진행 중인 작업의 중간 단계, 임시 계획, 최근 검색된 관련 정보 등을 저장하는 버퍼. 현재 세션 내에서 유지되지만, 장기 기억보다는 짧습니다.
*   **장기 기억 (Long-Term Memory)**: 에피소드, 의미론적 지식, 도구 사용법, 에이전트의 페르소나와 같은 영구적인 정보. 주로 RAG를 통해 접근합니다.
