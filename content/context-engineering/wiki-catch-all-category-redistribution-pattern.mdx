`wiki-category-health-rebalance-decision-framework` 의 결정 테이블은 cross-sim ≥ 0.99 → 머지를 권장한다. 하지만 **catch-all 카테고리는 머지가 아니라 재분배가 정답**이다.

## catch-all 카테고리의 특성

카테고리 X 가:
1. 원래 좁은 도메인으로 설계됨 (예: `harness-engineering` = 허브 아키텍처 메타 항목)
2. 시간이 지나며 "어디 넣을지 모르겠는" 항목들의 기본 착지점이 됨
3. 결과: 185개 항목, cross-sim 0.99, coherence 0.85 미만

이 상태에서 단순 머지 (`harness-engineering` → `context-engineering`) 를 하면 두 번째 catch-all 이 생긴다.

## 세 번째 옵션: 재분배

| 상황 | 기존 옵션 | 재분배 옵션 |
|---|---|---|
| cross-sim ≥ 0.99 + 카테고리 정체성 불명확 | 머지 | X |
| cross-sim ≥ 0.99 + **카테고리 core 는 유효** | X | **outlier 이동, 카테고리 유지** |

**판단 기준**: 카테고리에서 outlier 를 제거했을 때 남은 항목들이 coherent 한 집합을 이루는가?

## 2026-07-02 실증 (cycles 1274–1278)

`harness-engineering` (185 entries, N=240 outlier 분석):

- **제거 전**: coherence 불량, context-engineering ↔ cross-sim 0.993
- **제거 기준**: 다른 카테고리 centroid 와 유사도 +0.03 이상 차이나는 172개 이동
- **제거 후**: 14 entries — 전부 develop-cycle-hub 시스템 자체 메타 항목 (agentic-chain-*, skill-evolution-*, develop-cycle-*) → coherent

14개 잔존 항목:
- `agentic-chain-distribution-phase-fingerprint`
- `skill-evolution-oscillation-skip-condition-steady-state`
- `develop-cycle-positive-streak-recognition`
- 등 (모두 허브 자체 아키텍처 / 사이클 패턴)

`harness-engineering` 카테고리는 "허브 self-documentation 전용 카테고리"로 정체성 복원. 머지했다면 context-engineering 에 이 14개가 묻혀 discoverable 이 저하됐을 것.

## 재분배 패턴 적용 조건

1. **카테고리 core 항목 존재**: 전체의 10~20% 가 원래 도메인 정의에 맞음
2. **Outlier 비율 높음**: 80%+ 항목이 사실 다른 카테고리 소속
3. **Cross-sim 높지만 의도적 분리**: 예. `harness-engineering` (인프라/워크플로) vs `context-engineering` (프롬프트/LLM) — 다른 도메인

## 재분배 vs 머지 결정 트리

```
cross-sim ≥ 0.99?
  ├── NO: rebalance 불필요
  └── YES:
        카테고리 outlier 제거 후 core 10+ entries 남는가?
          ├── YES: 재분배 (outlier 이동, 카테고리 유지)
          └── NO: 
                core entries 가 다른 카테고리에 흡수 가능한가?
                  ├── YES: 머지
                  └── NO: GATE_CLUSTER 재검토 (10개 미달이면 통합)
```

## Anti-Pattern

**cross-sim 기계적 머지**: 두 카테고리가 centroid 상 가깝더라도, catch-all 이 원인이면 outlier 제거 후 centroid 가 멀어진다. 제거 전 cross-sim 은 "catch-all 오염" 신호이지 "진짜 같은 도메인" 신호가 아님.
