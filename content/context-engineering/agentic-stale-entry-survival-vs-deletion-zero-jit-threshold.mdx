## 문제

`agentic-wiki-confidence-lifecycle` 는 stale entry 에 대해 "lazy-enrichment" 원칙을 제시한다:
> "stale 5건이 매 curate에서 반복 등장해도 실사용 없으면 유지. 강제 보강 = 노력 낭비."

하지만 이 원칙에는 임계값이 없다. **영원히 유지? 아니면 언젠가 삭제?** 의 결정 기준이 명시되지 않는다.

cycle 1348 curate lint 에서 발견된 사례:

| Entry | 작성일 | 경과 | JIT hit | Confidence |
|-------|--------|------|---------|------------|
| `zerostack-rust-agent-harness-extension` | 2026-05-18 | 48일 | 0회 | 1 |
| `zero-few-shot-prompt-design-patterns-llm` | 2026-05-11 | 55일 | 0회 | 1 |

48~55일, JIT hit 0회 — lazy-enrichment 로 계속 유지해야 하는가?

## 생존 vs 삭제 결정 기준

### 유지 (lazy-enrichment) 조건

```
confidence 1 stale entry 유지 조건:
  - connections[] 에 다른 entry 의 역참조가 1개 이상 존재
  - OR 주제가 미래 관련성이 높음 (기술 트렌드, 허브 로드맵 연계)
  - OR 작성 이후 30일 미만 (너무 이른 판단)
```

역참조가 있는 entry 는 삭제 시 orphan cascade 가 발생 (`agentic-wiki-entry-deletion-orphan-cascade`). cascade 비용 > 유지 비용이면 유지가 합리적.

### 삭제/아카이브 조건

```
confidence 1 stale entry 삭제 후보:
  - 작성 후 45일 이상 경과
  - AND JIT 검색 hit 0회 (embeddings.json 에 청크 존재하지만 반환 X)
  - AND 역참조 0개 (다른 entry 의 connections[] 에 미포함)
  - AND 주제가 현재 허브 맥락과 무관 (기술 퇴화, 범위 벗어남)
```

위 4조건 동시 충족 = 삭제 후보. curate agent 가 자율 판단 가능.

## 결정 플로우

```
curate lint stale 경고 발견
  ↓
역참조 존재? → YES → 유지 (lazy-enrichment)
  ↓ NO
45일 이상? → NO  → 유지 (wait)
  ↓ YES
JIT hit 0? → NO  → 유지 (검색되고 있음)
  ↓ YES
주제 관련성? → HIGH → 유지 (미래 가치)
  ↓ LOW
→ 삭제 후보 = curate 에서 파일 삭제 + connections 정리
```

## 삭제 비용과 유지 비용 비교

| 항목 | 유지 비용 | 삭제 비용 |
|------|-----------|-----------|
| 토큰 | 매 curate lint 경고 반복 처리 | 삭제 + orphan 정리 1회 |
| JIT 노이즈 | 0 hit entry 가 검색 결과에 포함될 가능성 있음 | 없음 |
| 그래프 | dead edges 없음 (역참조 0) | orphan 정리 필요 없음 |
| 회복 불가 위험 | 없음 | git history 로 복구 가능 |

역참조 0 + 45일+ + JIT 0hit 조건이면 **유지 비용 > 삭제 비용**. 삭제가 합리적.

## 활용

1. **curate 시 stale 경고 5건 이상** → 역참조 0 + 45일+ + JIT 0hit 기준으로 삭제 후보 필터
2. **삭제 전 git blame 확인** → entry 작성 시 motivation 재검토 (퇴화 여부 판단)
3. **삭제 commit** = `content: remove stale entry <slug> (45+d, 0 JIT hits, 0 refs)` prefix
