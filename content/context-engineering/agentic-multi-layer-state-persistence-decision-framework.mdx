## 문제

자율 에이전트 루프 (develop-cycle 등) 에서 사이클마다 다양한 발견/결정/상태를 기록해야 한다. 저장 위치가 5개 이상인데, 잘못 선택하면:

- **정보 노이즈**: 메모리에 일시적 사이클 결과 누적 → 미래 세션에 irrelevant context 주입
- **정보 손실**: cycle_state 에 사용자 결정 필요 사항 박제 → 다음 사이클이 읽어도 행동 X
- **staleness**: TODOS.md 에 자동화로 해소 가능한 항목 → 사람이 "왜 아직 여기 있지?" 혼란

정보의 올바른 레이어 배치 = 에이전트 시스템의 장기 maintainability 핵심.

## 5계층 구조

```
┌────────────────────────────────────────────────────────────────┐
│  Layer 5: auto-memory    (~/.claude/projects/.../memory/)      │
│  용도: 사용자 선호·규칙·프로젝트 맥락                           │
│  timescale: 무기한 (수 개월)  audience: 미래 LLM 세션           │
├────────────────────────────────────────────────────────────────┤
│  Layer 4: TODOS.md       (repo root)                           │
│  용도: 사용자 결정 대기 항목 (R6 영역)                           │
│  timescale: 해소될 때까지  audience: 사람 (PM 뷰)               │
├────────────────────────────────────────────────────────────────┤
│  Layer 3: git commit     (history + message)                   │
│  용도: 코드 변경 사유·내용                                       │
│  timescale: 영구  audience: 미래 개발자·LLM                     │
├────────────────────────────────────────────────────────────────┤
│  Layer 2: cycle_state    (~/.develop-cycle-hub/cycles/N.json)  │
│  용도: 직전 N 사이클 결과 machine carryover                     │
│  timescale: 3~5 사이클 lookback  audience: 다음 사이클 LLM      │
├────────────────────────────────────────────────────────────────┤
│  Layer 1: handoff        (~/.gstack/projects/.../checkpoints/) │
│  용도: 현재 세션 context 스냅샷 (중단 대비)                     │
│  timescale: 세션 단위  audience: 동일 세션 재연결 LLM            │
└────────────────────────────────────────────────────────────────┘
```

## 결정 테이블

| 정보 유형 | 올바른 레이어 | 이유 |
|---|---|---|
| 이번 사이클 chain 선택 / outcome | cycle_state JSON | 다음 3 사이클 lookback input |
| 코드·스크립트·docs 변경 이유 | git commit message | 감사 추적, 영구 보존 |
| 사용자가 결정해야 할 것 (R6 영역) | TODOS.md | 사람 가시성 필요 |
| 사용자 선호·규칙·피드백 | auto-memory | 미래 세션에서도 유지 |
| 이번 세션 작업 중간 상태 | handoff | 세션 재연결 시만 필요 |
| 임시 에러 / debug log | 아무 레이어도 X | 노이즈. 해소 후 삭제 |
| 위키 entry 내용 | content/ MDX | JIT 검색 인덱스 |
| 반복 발생 패턴 (N≥2) | memory `meta-pattern` + wiki entry | 구조화된 지식화 |

## Anti-pattern — 레이어 혼용 실패 사례

### 1. cycle_state에 사용자 결정 항목 박제
```json
// ❌ 잘못된 박제
{
  "retro": {
    "todos_added": ["git merge 해주세요"]
  }
}
```
사용자는 cycle_state JSON 안 읽음. → **TODOS.md 에 명시적 항목 추가해야 함**.

### 2. auto-memory에 임시 사이클 결과 박제
```markdown
// ❌ 잘못된 메모리
cycle 879 explore-idea chain으로 entry #225 생성 완료
```
사이클 결과는 수십 회 후 stale. → **cycle_state JSON 에만 박제**. 메모리는 시간 무관 규칙만.

### 3. TODOS.md에 자동화 처리 가능 항목 방치
```markdown
// ❌ 자가 검열 패턴
## [PENDING] wiki lint clean 실행 필요
```
에이전트가 자율 처리 가능한 항목을 TODOS 에 박제 = **미결 목록 bloat**. → 자율 처리하고 cycle_state outcome 에 결과만 박제.

### 4. 레이어 간 동기화 없이 중복 박제
같은 내용을 git commit message + cycle_state retro.summary + TODOS.md 에 모두 박제 → 어느 것이 최신인지 불명. **단일 진실 원천 원칙**: 레이어별 역할 분리 유지.

## 레이어 composition 패턴

잘 설계된 사이클의 정보 흐름:

```
사이클 N 실행 중
  ├── 코드 변경 → git commit (변경 사유 포함)
  ├── 사용자 결정 필요 발견 → TODOS.md 항목 추가
  ├── 규칙 위반/피드백 발견 → auto-memory 갱신
  └── 사이클 끝
        ├── cycle_state JSON 박제 (chain/outcome/retro)
        └── handoff save (선택, 세션 중단 대비)

다음 사이클 N+1 진단
  ├── cycle_state JSON 읽기 (직전 3 사이클 lookback)
  ├── TODOS.md 읽기 (R6 대기 항목 확인)
  ├── auto-memory 활성 (세션 시작 시 주입)
  └── git log (변경 히스토리 확인)
```

## 실무 기준

- **새 사이클 발견 사항** → cycle_state JSON 만. 메모리 X.
- **사용자 직접 확인 필요** → TODOS.md. 에이전트 자율 처리 가능이면 X.
- **같은 실수 2번+** → auto-memory feedback. 한 번은 cycle_state 로 충분.
- **코드 변경 동반 결정** → git commit message 에 WHY 포함.
- **세션 재연결 준비** → handoff. 재연결 계획 없으면 cycle_state 로 충분.

## Quiz

- question: 에이전트 루프에서 "사용자가 git merge 여부를 결정해야 한다"는 발견을 했을 때, 가장 적절한 박제 위치는?
  choices:
    - cycle_state JSON retro.summary
    - auto-memory (feedback 타입)
    - TODOS.md (R6 대기 항목)
    - git commit message
  answer: 2
  explanation: 사용자 결정이 필요한 R6 영역은 TODOS.md 에 명시적 항목으로 추가. cycle_state 는 machine-readable 용도라 사용자가 직접 읽지 않음. auto-memory 는 사용자 규칙/선호 용도. git commit 은 코드 변경 용도.
