## 문제

```typescript
// ❌ 안티패턴: 하드코딩 기준선
const BASELINE_ACCURACY = 0.32;  // 언제 측정한 값인가?

function FactorAccuracyTable({ accuracy }) {
  return (
    <span>{accuracy > BASELINE_ACCURACY ? "↑ 기준 상회" : "↓ 기준 미달"}</span>
  );
}
```

모델이 개선되어 평균 정확도가 0.45 → 0.52 로 올라가도 BASELINE_ACCURACY = 0.32 그대로면:
- 실제로 평균 이하인 팩터도 "기준 상회" 표시
- 비교 의미 자체가 소멸

## 실측 사례 (moneyball cycle 1521, 2026-07-08)

- `FactorAccuracyTable` 의 `stale BASELINE_ACCURACY` 상수 제거
- 기준선 = 최근 N 게임 전체 팩터 평균으로 동적 계산
- Fix commit: `065d4c97` (develop-cycle/baseline-accuracy-dynamic-wave-142)

## 언제 발생하나

1. 초기 구현 시 "적당한 숫자" 로 하드코딩
2. 모델이 반복 개선됨 (새 피처, 데이터 확장, 알고리즘 개선)
3. 하드코딩 값은 갱신되지 않음 → stale
4. 코드 리뷰 시 "0.32가 왜 이 값인가?" 설명 불가

## 해결 패턴

```typescript
// ✅ 동적 기준선
function FactorAccuracyTable({ factors, accuracy }) {
  const meanAccuracy = factors.reduce((s, f) => s + f.accuracy, 0) / factors.length;
  return (
    <span>{accuracy > meanAccuracy ? "↑ 평균 상회" : "↓ 평균 미달"}</span>
  );
}
```

또는: 기준선을 API에서 받아오기 (최근 N일 평균, 시즌 평균 등).

## 점검 기준

코드에서 `BASELINE_*`, `DEFAULT_*`, `THRESHOLD_*` 상수를 발견하면:
1. 이 값이 언제, 어떤 데이터로 측정되었는가?
2. 모델/데이터가 이후 변경되었는가?
3. 값을 동적으로 계산할 수 있는가?

[question-own-defaults](project-ops/question-own-defaults) 프로토콜 적용 대상.
