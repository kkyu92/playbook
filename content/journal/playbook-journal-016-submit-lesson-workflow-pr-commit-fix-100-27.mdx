## 원본

~~~

push event 의 head_commit 만 검사하던 현행 로직은 PR 머지 시 GitHub default merge commit 메시지 ("Merge pull request #N from ...") 가 4 prefix 미해당이라 silent skip. PR #26 머지 시 dispatch skip 발견 (run 25161393739, 1s) — 직접 push lesson commit 만 정상 fire (run 25143854720, 7s).

해결: commits 배열 loop 로 머지 commit 안에 포함된 lesson commit 검출. head_commit 우선 (직접 push 일반 케이스) + 매칭 없으면 commits 배열 jq filter (PR 머지 케이스). 매칭 commit 첫 번째 사용 (id + message + prefix).

- Why: silent dispatch skip = 양방향 흡수 흐름 깨짐. silent drop 진단 비용 큼 (feedback_gh_actions_cron_unreliable 패턴). PR 머지 = 가장 자연스러운 워커→허브 lesson 흐름이라 이게 silent skip 되면 100% 자동화 목표 거리.
- Impact: 미래 모든 lesson commit (직접 push + PR 머지 + squash) 모두 dispatch fire. 사용자 manual 부담 X.
- 적용 범위: 머니볼 즉시 + blog-autopilot Phase 5 진입 시 동일 패턴 (submit-lesson.yml 신규 작성 시).

## 분석

### 갭 정체 — head_commit 단독 검사

submit-lesson workflow의 `if:` 조건이 `github.event.head_commit.message` 만 4 prefix (`lesson:` / `policy:` / `feedback:` / `memory:`) 매칭 검사. push event 안의 `commits[*]` 배열은 보지 않음.

PR 머지 패턴별 head_commit 결과:

| 머지 방식 | head_commit 메시지 | 4 prefix 매칭 | dispatch |
|---|---|---|---|
| 직접 push | 원본 commit msg 그대로 | ✅ (lesson:/policy:/... 시작 시) | fire |
| Squash merge | PR title 또는 합쳐진 메시지 | ✅ (PR title에 prefix 있을 시) | fire |
| Merge commit (no squash) | `Merge pull request #N from ...` | ❌ (항상 미매칭) | **silent skip** |
| Rebase merge | 원본 commit msg 그대로 | ✅ | fire |

→ Merge commit 만 silent skip. 본 케이스는 R6 정책 박는 PR #26 (`170c059 Merge pull request #26 ...`) 머지에서 발견.

### 발견 시퀀스 (같은 세션 내)

1. PR #26 (R6 정책) merge commit 머지 → main `170c059`
2. submit-lesson run 25161393739 **skipped (1s)** 관찰
3. 비교 — 직전 직접 push lesson commit (`62ad494`) 은 run 25143854720 **success (7s)**, 허브 dispatch fire
4. 갭 진단 + fix 결정 (양방향 흡수 100% 목표 정합)
5. PR #27 작성 + squash merge → main `5e822ca`
6. submit-lesson run 25161944646 **success (10s)** → 허브 worker-lesson run 25161950495 **success (24s)** → 허브 PR #85 자동 생성
7. 같은 세션 e2e 자연 검증 완료

## 교훈

1. **Silent dispatch skip = silent drop 패턴 동족**. `feedback_gh_actions_cron_unreliable` 정신 — silent fail 진단 비용 큼. silent dispatch skip 도 양방향 흡수 회로 끊김 → 사용자 인지 못 하면 0 으로 수렴. **즉시 fix 정합**.

2. **PR 머지 = 가장 자연스러운 워커→허브 흐름**. 직접 push 패턴은 사용자 직접 작업 또는 자동화 fire 결과. PR 머지는 표준 협업 흐름. 이게 silent skip 되면 100% 자동화 목표 거리. R6 (자율 수정 범위) 와 별개 차원의 인프라 갭.

3. **Dogfood = PR 자체가 검증 회로**. 같은 세션 내 fix → squash merge → e2e 자연 검증. 별도 monitoring 인프라 / 의도적 검증 PR 필요 X. 본 PR 자체가 양방향 흡수 회로 — 머지하면 회로 닫힘.

4. **R6 차단 영역 작업도 사용자 GO 시 진행 가능**. R6 의 자율 차단 의도는 **AI 자동 fire 시점**. 사용자 명시 GO 받은 manual 작업 (이번 세션 PR #27) 은 R6 와 모순 X. 사용자 review + manual squash merge 로 안전.

5. **자가 의심 → 즉시 fix 패턴**. 첫 추천 (α: evidence 박제만 + 자연 운영) 이 100% 목표 거리 자가 의심 → γ (workflow 갱신 PR) 으로 정정. `feedback_question_own_defaults` 정신 — 사용자 묻기 전에 AI 가 먼저 flag.
