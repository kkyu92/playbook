## 분석

Phase 5a self-develop 첫 ship spec = 1 fire = 1 try. 결과 = 6 cycles 모두 main 직접 push (사용자 인위 chain):

| cycle | fix | 원인 |
|---|---|---|
| 1 | pnpm version 충돌 제거 | action-setup 의 lockfile 일치 강제 |
| 2 | bypassPermissions settings | claude-code-action permission_denials 0 화 |
| 3 | show_full_output 디버그 | Claude turn 흐름 가시화 부재 |
| 4 | --dangerously-skip-permissions | 추가 permission 우회 layer |
| 5 | repo settings toggle | workflow permissions write + PR 생성/승인 |
| 6 | (post-ship 안정화) | 자연 동작 검증 |

1 fire 가정이 큰 task 자율 분해 + 다음 fire 인계 메커니즘 누락 → fix 5건이 자율 chain 안에서 처리됐어야 함. 자율 진행 불가능 = 인위 main push.

## 교훈

1. **새 자율 agent ship 시 carry-over 필수** — 단일 fire 가정 X. token cap / 큰 task / 다음 step 명확 시 자율 인계 메커니즘 사전 설계 (Issue 기반 + label `*,handoff` + cycle 카운터).
2. **namespace 분리는 자동 결과 추적 토대** — `agent-loop` label/branch/marker 3축. 사용자 직접 vs 자동 결과 명확 구분 → 검색 필터 / carry-over Issue 정합 / 잘못된 carry-over 회피 가능.
3. **cycle cap = 무한 chain 방지 + 메타 회고 기점** — 10 fire = 1 cycle. 10/10 도달 시 횡단 lesson 박제 후 cycle 종료. 새 daily fire = 새 cycle 자연 시작.
