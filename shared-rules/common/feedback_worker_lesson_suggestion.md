워커 프로젝트 Claude 세션에서 **커밋 메시지 작성 / 제안 시**, 해당 커밋이 **lesson 성 가치** 를 갖는지 자가 판단해 사용자에게 `lesson:` 접두사 붙일지 물어본다. 붙이면 워커 workflow 의 `Submit lesson` step 이 허브(playbook) 의 `auto-ingest` 를 트리거해 Journal draft PR 자동 생성.

**Why:** 교훈성 있는 작업이 평범한 커밋으로 흘러가면 허브에 박제될 기회 상실 → 다른 워커가 같은 문제 다시 겪음 → 복리 성장 루프 단절. 인간이 lesson 여부를 매번 기억하기 어려우니 Claude 가 커밋 순간 자동 상기.

**How to apply:**

### Trigger (이것만 적용)

사용자가 워커 세션에서 커밋 메시지를 작성·제안받을 때. 예: "이제 커밋하자", "/ship", "git commit 메시지 제안해줘", `git add` 후 커밋 직전 맥락.

### Lesson 성 신호 (하나라도 매칭 시 제안)

1. **3회 이상 디버깅 사이클** — 같은 문제로 여러 번 되돌아왔고 이번에 근본 해결
2. **새 패턴 / 엣지케이스 발견** — 기존 엔트리에 없고 2+ 프로젝트에 이식 가능한 추상 패턴
3. **인프라 / 아키텍처 결정** — 변경이 광범위 영향 (빌드, 배포, 데이터 모델, 에러 처리 전략)
4. **Cross-cutting 교훈** — 특정 도메인 해결책이 다른 도메인에도 쓸만한 일반화 여지
5. **재발 방지 가드** — "이런 실수 다시 안 하려면 X" 성격의 변경

### 제외 (절대 제안 안 함)

- 단순 오타 / 포매팅 / 주석 수정
- 단발 버그 fix 이며 재발 가능성 낮음
- 의존성 업데이트
- 설정 값 단순 변경
- WIP / 중간 커밋

### 제안 포맷

판단 결과 lesson 성 있다고 판단되면 사용자에게 1문장으로:

> "이 커밋은 `{신호 종류}` 에 해당해 lesson 후보로 보입니다. 커밋 메시지에 `lesson:` 접두사 붙여서 허브에 박제할까요?"

선택지:
- **Yes**: 커밋 메시지 앞에 `lesson:` 붙임. 예: `lesson: 백테스트 엣지 — 0승 팀 평균 처리`
- **No**: 일반 커밋으로 진행

사용자가 명확히 "lesson 아님" 선언하면 같은 세션 내 재제안 금지 (중복 질문 방지).

### 결과 흐름 (참고)

`lesson:` 접두사 붙은 커밋이 워커 workflow 로 detect 되면:
1. 워커 workflow 의 `Submit lesson` step 이 `repository_dispatch worker-lesson` 송신
2. 허브 `auto-ingest.yml` 수신
3. `raw-sources/` 저장 + Journal draft PR 자동 생성
4. 허브 세션에서 PR 보강 후 머지
5. `content/journal/` 에 박제 → 다음 워커 세션에 symlink 로 자동 전파

이게 복리 성장 양방향 루프의 워커→허브 축.

### 예외 / 판단 경계

- **애매하면 제안하는 쪽이 낫다**. lesson 을 놓치는 비용 > 불필요한 제안 1회
- 단 **같은 세션에서 2회 제안 후 모두 No** 면 그 세션 나머지는 제안 생략
- 사용자가 명시적으로 "지금 lesson 판단 필요 없어" 선언하면 세션 내 비활성화
