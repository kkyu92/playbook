세션 전환(`/handoff save` → 새 세션) 제안은 **사용자가 자가 인지하기 어려운 drift 신호**에만 한정. 자율적으로 컨트롤할 수 있는 신호로는 제안 금지.

**Why:** 사용자가 직접 정의한 규칙 (2026-04-17 대화). 주제 전환 / 커밋·PR 완성 / 30턴 돌파 같은 건 본인이 컨트롤 가능하니 내가 끼어들 필요 없음. 반대로 "같은 파일 반복 read" 나 "결정 번복" 같은 건 본인이 인지하기 어려워서 내가 감지·경고해야 함.

**How to apply:**

**제안 금지** (사용자 자율 영역):
- 주제 완전 전환 시점
- 커밋·PR·기능 완성 직후
- 대화 30턴 돌파

**제안 발동** (자동 감지):

| 신호 | 강도 |
|------|------|
| 같은 파일 3회 이상 re-read | 가볍게 언급 ("이 파일 여러 번 보고 있음 — 맥락 포화 신호") |
| 결정 번복 / 이전 맥락 혼동 | 명확히 지적 ("직전에 X라고 했는데 지금 Y — drift 신호") |
| Context 퍼센트 돌파 | 구간별 차등 (아래) |

**Context 퍼센트 임계값 (Claude Code 1M context 기준)**:

| 구간 | 액션 |
|------|------|
| ~50% | 아무것도 안 함 |
| 50~70% | 작업 끝날 때 한 번 언급: "참고, context 60% 사용 중" |
| 70~85% | 적극 제안: "현재 작업 커밋 직후 /handoff save → 새 세션 권장" |
| 85%+ | 강한 권고 + 다음 작업 **시작 전** 저장 요청 |

**조합 규칙**: drift 신호 (re-read 또는 번복) 하나라도 발동 + context 50% 초과 시 → 즉시 70% 구간 대우. 두 신호 겹치면 체감 drift 가 훨씬 심함.

**제안 형식**:
> "👉 {신호 설명}. 새 세션으로 넘어가는 거 어때? (/handoff save 해두면 드리프트 없이 복원됨) — 계속해도 OK"

강요 금지. 거부 쉽게.
